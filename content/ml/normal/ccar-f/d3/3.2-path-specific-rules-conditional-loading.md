## പാത-നിർദിഷ്ട നിയമങ്ങൾ — വ്യവസ്ഥാധിഷ്ഠിത ലോഡിങ്

ഒരൊറ്റ പ്രോജക്ടിനുള്ളിൽ, ഏത് ഭാഗത്താണ് നിങ്ങൾ എന്നതനുസരിച്ച് വളരെ വ്യത്യസ്തമായ കീഴ്‌വഴക്കങ്ങൾ ഉണ്ടാകാം — ടെസ്റ്റിങ് കോഡ് പ്രൊഡക്ഷൻ കോഡിൽ നിന്ന് വ്യത്യസ്ത നിയമങ്ങൾ പിന്തുടരുന്നു, സ്വയമേവ ഉണ്ടാക്കിയ ഫയലുകൾ കൈകൊണ്ട് എഴുതിയവയിൽ നിന്ന് വ്യത്യസ്തം, infrastructure സ്ക്രിപ്റ്റുകൾ UI കംപോണന്റുകളിൽ നിന്ന് വ്യത്യസ്തം. ഇവയെല്ലാം ഒരു വലിയ CLAUDE.md-ൽ തിരുകിക്കയറ്റിയാൽ, ഇപ്പോൾ തൊടുന്ന ഫയലിന് ഒരു ചെറിയ ഭാഗം മാത്രം പ്രസക്തമാകുമ്പോഴും Claude-ന് എല്ലാം എപ്പോഴും context-ൽ വഹിക്കേണ്ടിവരും. ഒരു നിയമം *ഏതൊക്കെ ഫയലുകൾക്ക് ബാധകമാണെന്ന്* പ്രഖ്യാപിക്കാൻ അനുവദിച്ചുകൊണ്ട് പാത-നിർദിഷ്ട നിയമങ്ങൾ ഇത് പരിഹരിക്കുന്നു, അങ്ങനെ യഥാർഥത്തിൽ പ്രസക്തമാകുമ്പോൾ മാത്രം അത് context-ലേക്ക് വരുന്നു.

### ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു

ഇത്തരം നിയമങ്ങൾ `.claude/rules/`-നുള്ളിൽ വെവ്വേറെ markdown ഫയലുകളായി നിലനിൽക്കുന്നു, ഓരോ ഫയലിലും ഒരു ചെറിയ frontmatter ബ്ലോക്ക് ഉണ്ട് (ബ്ലോഗ് പോസ്റ്റുകളിലോ രേഖാ സൈറ്റുകളിലോ കണ്ടിട്ടുള്ള YAML frontmatter-ന് സമാനം) അത് ഒരു `paths` ഫീൽഡ് വ്യക്തമാക്കുന്നു — glob മാതൃകകളുടെ ഒരു നിര. ഒരു ഫയലിൽ പ്രവർത്തിക്കാൻ പോകുമ്പോൾ, ഏതൊക്കെ നിയമ ഫയലുകൾക്ക് പൊരുത്തപ്പെടുന്ന പാത മാതൃകകളുണ്ടെന്ന് Claude പരിശോധിക്കുന്നു, അവ മാത്രം സജീവ context-ലേക്ക് ലോഡ് ചെയ്യുന്നു.

ഉദാഹരണത്തിന്, ടെസ്റ്റിങ് കീഴ്‌വഴക്കങ്ങൾക്കായുള്ള ഒരു നിയമ ഫയൽ ഇങ്ങനെയിരിക്കാം:

```
# File: .claude/rules/testing.md
---
paths: ["**/*.test.tsx", "**/*.spec.ts"]
---

All tests must follow the AAA pattern (Arrange, Act, Assert).
Every function must have at least one unit test.
Use describe() for groups and it() for individual tests.
```

`paths` നിര glob വ്യാകരണം ഉപയോഗിക്കുന്നു — `**/*.test.tsx` എന്നാൽ "ഏത് നെസ്റ്റഡ് ഫോൾഡറിലുമുള്ള, `.test.tsx`-ൽ അവസാനിക്കുന്ന ഏത് ഫയലും." ഈ മാതൃകകളിലൊന്നിനോട് പൊരുത്തപ്പെടുന്ന ഒരു ഫയൽ Claude തിരുത്തുമ്പോൾ മാത്രമേ ടെസ്റ്റിങ് കീഴ്‌വഴക്ക ടെക്സ്റ്റ് context-ലേക്ക് വരുന്നുള്ളൂ. പകരം Claude ഒരു സാധാരണ കംപോണന്റ് ഫയലാണ് തിരുത്തുന്നതെങ്കിൽ, ഈ നിയമം നിഷ്ക്രിയമായി തുടരുന്നു, ശബ്ദം കൂട്ടുന്നില്ല.

### എന്തുകൊണ്ട് വെറും directory-തല CLAUDE.md പോരാ?

ഒരു ലളിതമായ directory-തല `CLAUDE.md`-നെക്കാൾ പാത-നിർദിഷ്ട നിയമങ്ങൾ എപ്പോൾ മെച്ചമാകുന്നു എന്ന് കൃത്യമായി പറയേണ്ടതുണ്ട്. Directory-തല ഫയലുകൾ *ഫോൾഡർ ശ്രേണിയിലെ സ്ഥാനം* അനുസരിച്ചാണ് പരിധി നിർണയിക്കുന്നത് — ഫയൽ തരം എന്തായാലും ഒരു ഫോൾഡറിനുള്ളിലെ എല്ലാത്തിനും അവ ബാധകമാണ്. പാത-നിർദിഷ്ട നിയമങ്ങൾ *മാതൃക* അനുസരിച്ചാണ് പരിധി നിർണയിക്കുന്നത്, അതായത് അവയ്ക്ക് ഒരേസമയം പല ഫോൾഡറുകളിലേക്കും എത്താൻ കഴിയും.

| സമീപനം | പരിധി നിർണയ സംവിധാനം | ഏറ്റവും അനുയോജ്യം |
|---|---|---|
| Directory-തല `CLAUDE.md` | ഭൗതിക ഫോൾഡർ സ്ഥാനം | പ്രസക്തമായ എല്ലാ ഫയലുകളും ഒരുമിച്ചുള്ള നിയമങ്ങൾ (ഉദാ: `backend/`-ന് കീഴിലുള്ളതെല്ലാം) |
| glob `paths`-ഓടെ `.claude/rules/` | ഫോൾഡർ എന്തായാലും, ഫയൽ പേര്/എക്സ്റ്റൻഷൻ മാതൃക | കോഡ്ബേസിലുടനീളം ചിതറിക്കിടക്കുന്ന ഒരു ഫയൽ *തരത്തിനുള്ള* നിയമങ്ങൾ (ഉദാ: ഏത് ഫോൾഡറിലായാലും എല്ലാ `*.test.tsx` ഫയലും) |

ടെസ്റ്റ് ഫയലുകളാണ് ക്ലാസിക് ഉദാഹരണം: അവ സാധാരണയായി ടെസ്റ്റ് ചെയ്യുന്ന സോഴ്സ് ഫയലുകൾക്ക് അടുത്തായി, ഡസൻ കണക്കിന് ഫോൾഡറുകളിൽ ചിതറിക്കിടക്കുന്നു. തൊട്ടടുത്തിരിക്കുന്ന ടെസ്റ്റ്-അല്ലാത്ത ഫയലുകളെ കൂടി ഉൾപ്പെടുത്താതെ "എല്ലാ ടെസ്റ്റ് ഫയലുകളും" വൃത്തിയായി ലക്ഷ്യമിടാൻ ഒരു directory-തല CLAUDE.md-ന് കഴിയില്ല. `.claude/rules/`-ലെ ഒരു glob-പരിധി നിയമത്തിന് കഴിയും.

> **💡 നുറുങ്ങ്:** നിങ്ങൾ ലക്ഷ്യമിടുന്നത് ഒരു *സ്ഥാനമല്ല*, ഒരു *ഫയൽ തരമോ പേരിടൽ മാതൃകയോ* ആണെങ്കിൽ എപ്പോഴും glob-പരിധി നിയമങ്ങൾ ഉപയോഗിക്കുക. "എവിടെയായാലും X-ൽ അവസാനിക്കുന്ന ഏത് ഫയലിനും ഈ നിയമം ബാധകമാണ്" എന്ന് എഴുതാൻ തോന്നുന്നുവെങ്കിൽ, ഒരു directory CLAUDE.md-ന് പകരം `.claude/rules/` ഉപയോഗിക്കാനുള്ള സൂചനയാണത്.

> **🌍 യഥാർഥ ഉദാഹരണം:** ഇടത്തരം വലുപ്പമുള്ള ഒരു SaaS ടീമിന് കോഡ്ബേസിലുടനീളം React കംപോണന്റുകളും അവയുടെ ടെസ്റ്റുകളും ഒരേ ഫോൾഡറുകളിൽ ഒരുമിച്ചാണ് (40+ feature ഫോൾഡറുകളിലായി `Button.tsx`-ന് അടുത്ത് `Button.test.tsx`, അങ്ങനെ). എല്ലാ ടെസ്റ്റ് ഫയലും AAA മാതൃകയും ആവശ്യമായ coverage-ഉം പാലിക്കണമെന്ന് അവർ ആഗ്രഹിക്കുന്നു, പക്ഷേ Claude കംപോണന്റ് മാത്രം തിരുത്തുമ്പോൾ ആ മാർഗനിർദേശം context കുഴപ്പത്തിലാക്കരുത്. അവർ `**/*.test.tsx`, `**/*.spec.ts` എന്നിവയിലേക്ക് പരിമിതപ്പെടുത്തിയ `.claude/rules/testing.md` ഉണ്ടാക്കുന്നു. ഇപ്പോൾ ഒരു ഡെവലപ്പർ "Button കംപോണന്റിൽ ഒരു loading spinner ചേർക്കുക" എന്ന് Claude-നോട് ആവശ്യപ്പെടുമ്പോൾ ടെസ്റ്റിങ് നിയമങ്ങൾ ഒരിക്കലും ലോഡ് ആകുന്നില്ല — Claude-ന്റെ context കംപോണന്റ് ശൈലീ കീഴ്‌വഴക്കങ്ങളിൽ കേന്ദ്രീകരിച്ചിരിക്കുന്നു. പക്ഷേ "പുതിയ spinner അവസ്ഥയ്ക്ക് ഒരു ടെസ്റ്റ് ചേർക്കുക" എന്ന് ആരെങ്കിലും ആവശ്യപ്പെടുന്ന നിമിഷം, ടെസ്റ്റുകൾ അടങ്ങിയ എല്ലാ ഫോൾഡറിനും വേണ്ടി മുപ്പത് വ്യത്യസ്ത directory-തല CLAUDE.md ഫയലുകൾ ആർക്കും വേണ്ടിവരാതെ, ടെസ്റ്റിങ് നിയമം സ്വയമേവ സജീവമാകുന്നു.
