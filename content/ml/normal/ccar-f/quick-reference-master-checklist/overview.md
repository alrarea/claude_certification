## പെട്ടെന്നുള്ള റഫറൻസും മാസ്റ്റർ ചെക്ക്‌ലിസ്റ്റും

### പരീക്ഷയുടെ അടിസ്ഥാന വിവരങ്ങൾ

| വിവരം | മൂല്യം |
|---|---|
| ചോദ്യങ്ങൾ | 60 |
| ദൈർഘ്യം | 120 മിനിറ്റ് |
| വിജയിക്കാനുള്ള സ്കോർ | 720 / 1000 |
| പരീക്ഷാ ഫീസ് | $125 USD |
| നൽകുന്ന സാഹചര്യങ്ങൾ | 6-ൽ 4 (യാദൃച്ഛികം) |
| സർട്ടിഫിക്കറ്റിന്റെ കാലാവധി | 12 മാസം |

| വർഷത്തിൽ പരമാവധി ശ്രമങ്ങൾ | 4 തവണ |

പഠന ആസൂത്രണത്തിനെന്നപോലെ പരീക്ഷാ ദിവസത്തെ തന്ത്രത്തിനും ഈ സംഖ്യകൾ പ്രധാനമാണ്: 120 മിനിറ്റിൽ 60 ചോദ്യങ്ങൾ എന്നത് ഓരോ ചോദ്യത്തിനും ശരാശരി 2 മിനിറ്റ് — ഓരോ തവണയും തുടക്കം മുതൽ ന്യായവാദം ചെയ്യുന്നതിനു പകരം ഒരു ചോദ്യത്തിനു പിന്നിലെ മാതൃക വേഗം തിരിച്ചറിയാൻ ലക്ഷ്യമിടേണ്ടത്ര ഇറുക്കമാണ് ഇത്.

### കൃത്യമായി അറിഞ്ഞിരിക്കേണ്ട 12 നിയമങ്ങൾ

- `stop_reason == "end_turn"` കണ്ടാൽ മാത്രം agentic loop നിർത്തുക. ആവർത്തനങ്ങളുടെ എണ്ണമോ ടെക്സ്റ്റ് പാഴ്‌സിങ്ങോ ഒരിക്കലും അരുത്.
- Coordinator അവരുടെ task prompt-ൽ വ്യക്തമായി നൽകുന്നത് മാത്രമേ subagent-കൾക്ക് അറിയൂ. സ്വയമേവയുള്ള കൈമാറ്റമില്ല. ഒരിക്കലും.
- ഒരു multi-agent സിസ്റ്റത്തിൽ നിന്നുള്ള അപൂർണമായ ഫലം → coordinator-ന്റെ task decomposition വളരെ ഇടുങ്ങിയതായിരുന്നു.
- വലിയ പ്രത്യാഘാതമുള്ള നിയമങ്ങൾ (സാമ്പത്തികം, compliance, സുരക്ഷ) → prompt നിർദേശങ്ങളല്ല, hooks ഉപയോഗിക്കുക.
- PreToolUse hooks = നടപ്പാക്കുന്നതിനു മുൻപ് തടയുന്നു. PostToolUse hooks = നടപ്പാക്കിയ ശേഷം ലോഗ് ചെയ്യുന്നു/രൂപം മാറ്റുന്നു.
- പ്രോജക്റ്റ് root-ലെ CLAUDE.md = ടീം പങ്കിടുന്നത് (git-ൽ). ~/.claude/CLAUDE.md = വ്യക്തിപരം മാത്രം (git-ൽ അല്ല).
- Project command-കൾ (`.claude/commands/`) = പങ്കിടുന്നത്. വ്യക്തിപരമായ command-കൾ (`~/.claude/commands/`) = പ്രാദേശികം.
- JSON schema ഘടന ഉറപ്പാക്കുന്നു, സത്യമല്ല. സംഖ്യകൾ വാക്യഘടനാപരമായി സാധുവും യുക്തിപരമായി തെറ്റുമാകാം.
- നീണ്ട രേഖകളുടെ ഏറ്റവും മുകളിൽ നിർണായക ഉള്ളടക്കം വെക്കുക. Lost-in-middle പ്രഭാവം = നടുവിലെ ഉള്ളടക്കം വിട്ടുപോകുന്നു.
- Routing സംവിധാനം ഉണ്ടാക്കും മുൻപ് ടൂൾ വിവരണങ്ങൾ ശരിയാക്കുക. വിവരണങ്ങളാണ് എപ്പോഴും മൂലകാരണം.
- Message Batches API (50% വില കുറവ്, 24 മണിക്കൂർ വരെ) = തടസ്സപ്പെടുത്താത്ത ജോലികൾക്ക് മാത്രം. Merge-നു മുൻപുള്ള പരിശോധനകൾക്ക് ഒരിക്കലും അരുത്.
- CI/CD pipeline-കളിലെ Claude Code-ന് `-p` flag ഉപയോഗിക്കുക. അതില്ലാതെ, മനുഷ്യന്റെ ഇൻപുട്ടിനായി കാത്ത് pipeline തൂങ്ങിനിൽക്കും.

ഈ 12 നിയമങ്ങൾ പ്രധാനമാണ്, കാരണം ഓരോന്നും ആവർത്തിക്കുന്ന ഒരു പരീക്ഷാ മാതൃകയുടെ ഉത്തരമാണ്: ഒരു സാഹചര്യം ഒരു പരാജയം അവതരിപ്പിക്കുന്നു, പരിഹാരം മിക്കവാറും എപ്പോഴും ഈ നിയമങ്ങളിലൊന്ന് ശരിയായി പ്രയോഗിക്കലാണ്. ഇവ കൃത്യമായി അറിയുന്നത്, സമയ സമ്മർദത്തിൽ അടിസ്ഥാന തത്വങ്ങളിൽ നിന്ന് വീണ്ടും ചിന്തിക്കുന്നത് ഒഴിവാക്കിത്തരുന്നു.

### 6 പരീക്ഷാ കെണികൾ — ശരിയെന്ന് തോന്നിക്കുന്ന തെറ്റുത്തരങ്ങൾ

- "ഒരു system prompt നിർദേശം ചേർക്കുക" — ഉറപ്പായ പാലനം വേണ്ട നിയമമാകുമ്പോൾ തെറ്റ്. പകരം ഒരു hook ഉപയോഗിക്കുക.
- "കൈമാറ്റത്തിന് sentiment analysis" — തെറ്റ്. നിരാശ ≠ സങ്കീർണത. ഒരിക്കലും വിശ്വസനീയമായ ഒരു കൈമാറ്റ ട്രിഗറല്ല.
- "മോഡൽ സ്വയം പറയുന്ന ആത്മവിശ്വാസ സ്കോർ" — തെറ്റ്. സ്വന്തം ആത്മവിശ്വാസം വിലയിരുത്തുന്നതിൽ LLM-കൾ മോശമായി calibrate ചെയ്യപ്പെട്ടവയാണ്.
- "വലിയ context window" — lost-in-middle-ന് തെറ്റ്. ഉള്ളടക്കം എവിടെ വെക്കുന്നു എന്നത് വലിയ window ശരിയാക്കുന്നില്ല.
- "പല തവണ പ്രവർത്തിപ്പിച്ച് ശരാശരി എടുക്കുക" — തെറ്റ്. ഘടനാപരമായ പ്രശ്നങ്ങൾ ഇത് പരിഹരിക്കുന്നില്ല; ചെലവും latency-യും കൂട്ടുക മാത്രം ചെയ്യുന്നു.
- "N ആവർത്തനങ്ങൾക്ക് ശേഷം നിർത്തുക" — തെറ്റായ loop അവസാനിപ്പിക്കൽ. എപ്പോഴും stop_reason == "end_turn" കണ്ടാൽ നിർത്തുക.

ഈ കെണികൾ പ്രധാനമാണ്, കാരണം അവ ബോധപൂർവം യുക്തിസഹമെന്ന് തോന്നിക്കുന്ന വഴിതെറ്റിക്കലുകളാണ് — ഓരോന്നും ചോദ്യത്തിലേതിൽ നിന്ന് *വ്യത്യസ്തമായ* ഒരു പ്രശ്നം പരിഹരിക്കുന്ന യഥാർഥ രീതിയാണ്. ശരിയുത്തരം നേരിട്ട് ഓർത്തെടുക്കുന്നതിനെക്കാൾ വേഗമാണ് പലപ്പോഴും ഒരു കെണി തിരിച്ചറിയുന്നത്.

### ഓരോ ഡൊമെയ്നിനും ആവർത്തന ചെക്ക്‌ലിസ്റ്റ്

താഴെയുള്ള ഓരോ ഡൊമെയ്ൻ ചെക്ക്‌ലിസ്റ്റും ഒരു അന്തിമ സ്വയം പരിശോധനയാണ്: ഓരോ കള്ളിയും ഉറപ്പോടെ അടയാളപ്പെടുത്താൻ കഴിയുമെങ്കിൽ, പരീക്ഷയുടെ ആ ഭാഗത്തിന് നിങ്ങൾ തയ്യാറാണ്.

#### ഡൊമെയ്ൻ 1 — Agentic Architecture (27%)

- Agentic loop-ഉം നാല് stop_reason മൂല്യങ്ങളും വിശദീകരിക്കാൻ എനിക്ക് കഴിയും
- Subagent isolation എന്നാൽ context വ്യക്തമായി കൈമാറണം എന്ന് എന്തുകൊണ്ടെന്ന് എനിക്ക് അറിയാം
- അപൂർണമായ ഫലം = coordinator-ന്റെ വിഭജന പ്രശ്നം എന്ന് എന്തുകൊണ്ടെന്ന് ഞാൻ മനസ്സിലാക്കുന്നു
- ക്രമാനുഗതമോ സമാന്തരമോ ആയ subagent പ്രവർത്തനം എപ്പോൾ ഉപയോഗിക്കണമെന്ന് എനിക്ക് അറിയാം
- വിശ്വസനീയവും വിശ്വസിക്കാനാകാത്തതുമായ കൈമാറ്റ ട്രിഗറുകൾ എനിക്ക് തിരിച്ചറിയാനാകും
- Hooks (PreToolUse / PostToolUse) ഉം prompt നിർദേശങ്ങൾക്കു പകരം അവ എപ്പോൾ ഉപയോഗിക്കണമെന്നും ഞാൻ മനസ്സിലാക്കുന്നു
- Session management-ന് --resume-ഉം fork_session-ഉം എങ്ങനെ ഉപയോഗിക്കണമെന്ന് എനിക്ക് അറിയാം
- Programmatic enforcement-ഉം prompt അടിസ്ഥാന മാർഗനിർദേശവും ഞാൻ മനസ്സിലാക്കുന്നു

#### ഡൊമെയ്ൻ 2 — Tool Design & MCP (18%)

- MCP എന്താണെന്നും tools-ഉം resources-ഉം തമ്മിലുള്ള വ്യത്യാസവും എനിക്ക് അറിയാം
- സമാന ടൂളുകളെ വ്യക്തമായി വേർതിരിക്കുന്ന ഒരു നല്ല ടൂൾ വിവരണം എനിക്ക് എഴുതാനാകും
- ഒരു ടൂൾ വിവരണം മോശമാക്കുന്നത് എന്താണെന്ന് (അത് എന്തുകൊണ്ട് തിരഞ്ഞെടുക്കൽ പിഴവുകൾ ഉണ്ടാക്കുന്നു എന്നും) എനിക്ക് അറിയാം
- isError flag-ഉം 4 പിഴവ് വിഭാഗങ്ങളും ഞാൻ മനസ്സിലാക്കുന്നു
- .mcp.json (project) ഉം ~/.claude.json (വ്യക്തിപരം) ഉം തമ്മിലുള്ള വ്യത്യാസം എനിക്ക് അറിയാം
- Read, Edit, Grep, Glob എന്നിവയിൽ ഏതെപ്പോൾ ഉപയോഗിക്കണമെന്ന് എനിക്ക് അറിയാം
- tool_choice: auto / any / forced തിരഞ്ഞെടുക്കൽ ഞാൻ മനസ്സിലാക്കുന്നു
- വളരെയധികം ടൂളുകൾ പ്രകടനം മോശമാക്കുന്നുവെന്ന് എനിക്ക് അറിയാം

#### ഡൊമെയ്ൻ 3 — Claude Code (20%)

- 3 തല CLAUDE.md ശ്രേണിയും ഓരോ തലവും എന്തിനാണെന്നും എനിക്ക് അറിയാം
- Modular ക്രമീകരണത്തിന് @import-ഉം .claude/rules/-ഉം ഞാൻ മനസ്സിലാക്കുന്നു
- .claude/rules/-ൽ glob മാതൃകകളുള്ള path-scoping എങ്ങനെ പ്രവർത്തിക്കുന്നുവെന്ന് എനിക്ക് അറിയാം
- Project command-കളും വ്യക്തിപരമായ command-കളും അവ എവിടെ ഇരിക്കുന്നുവെന്നും എനിക്ക് അറിയാം
- Skill frontmatter ഞാൻ മനസ്സിലാക്കുന്നു: context:fork, allowed-tools, argument-hint
- Plan mode-ഉം നേരിട്ടുള്ള നിർവഹണവും എപ്പോൾ ഉപയോഗിക്കണമെന്ന് എനിക്ക് അറിയാം
- CI/CD സംയോജനത്തിന് -p flag-ഉം --output-format json-ഉം എനിക്ക് അറിയാം
- സ്വയം review ചെയ്യുന്നതിനെക്കാൾ സ്വതന്ത്ര review instance-കൾ കൂടുതൽ പ്രശ്നങ്ങൾ കണ്ടെത്തുന്നത് എന്തുകൊണ്ടെന്ന് ഞാൻ മനസ്സിലാക്കുന്നു

#### ഡൊമെയ്ൻ 4 — Prompt Engineering (20%)

- വാക്യഘടനാപരമായ കൃത്യതയും (ഘടന) അർഥപരമായ കൃത്യതയും (അർഥം) തമ്മിലുള്ള വ്യത്യാസം എനിക്ക് അറിയാം
- ഘടനാപരമായ ഔട്ട്പുട്ട് ഉറപ്പാക്കാൻ JSON schema-യോടു കൂടിയ tool_use എങ്ങനെ ഉപയോഗിക്കണമെന്ന് എനിക്ക് അറിയാം
- Nullable ഫീൽഡുകളും അവ എന്തുകൊണ്ട് hallucination തടയുന്നുവെന്നും ഞാൻ മനസ്സിലാക്കുന്നു
- Few-shot prompting എങ്ങനെ ഉപയോഗിക്കണമെന്നും അത് എപ്പോൾ ഏറ്റവും ഫലപ്രദമാണെന്നും എനിക്ക് അറിയാം
- Retry-with-feedback loop-കളും retry-കൾ എപ്പോൾ സഹായിക്കില്ലെന്നും ഞാൻ മനസ്സിലാക്കുന്നു
- Message Batches API-യും തത്സമയ API-യും എപ്പോൾ ഉപയോഗിക്കണമെന്ന് എനിക്ക് അറിയാം
- Multi-pass review ഞാൻ മനസ്സിലാക്കുന്നു: ഓരോ ഫയലിനുമുള്ള pass-കൾ + ഒരു integration pass
- "be conservative" പോലുള്ള അവ്യക്ത നിർദേശങ്ങളെക്കാൾ വ്യക്തമായ മാനദണ്ഡങ്ങൾ മെച്ചമാണെന്ന് എനിക്ക് അറിയാം

#### ഡൊമെയ്ൻ 5 — Context & Reliability (15%)

- Lost-in-middle പ്രഭാവവും ശരിയായ പരിഹാരങ്ങളും വിശദീകരിക്കാൻ എനിക്ക് കഴിയും
- സംഗ്രഹിക്കുമ്പോൾ പ്രധാനപ്പെട്ട കൃത്യമായ മൂല്യങ്ങൾ നഷ്ടപ്പെടാവുന്നത് എന്തുകൊണ്ടെന്ന് എനിക്ക് അറിയാം
- നീണ്ട session-കൾക്ക് scratchpad ഫയലുകളും /compact-ഉം എങ്ങനെ ഉപയോഗിക്കണമെന്ന് എനിക്ക് അറിയാം
- ഘടനാപരമായ പിഴവ് കൈമാറ്റവും പൊതുവായ പിഴവുകൾ എന്തുകൊണ്ട് പരാജയപ്പെടുന്നുവെന്നും ഞാൻ മനസ്സിലാക്കുന്നു
- ഏതൊക്കെ കൈമാറ്റ ട്രിഗറുകൾ വിശ്വസനീയമാണെന്നും ഏതൊക്കെ അല്ലെന്നും എനിക്ക് അറിയാം
- ഫീൽഡ് തല ആത്മവിശ്വാസ calibration-ഉം stratified sampling-ഉം ഞാൻ മനസ്സിലാക്കുന്നു
- Multi-agent സമന്വയത്തിലുടനീളം വിവര provenance എങ്ങനെ നിലനിർത്താമെന്ന് എനിക്ക് അറിയാം
- പല വിശ്വസനീയ ഉറവിടങ്ങളിൽ നിന്നുള്ള വൈരുധ്യമുള്ള ഡാറ്റ എങ്ങനെ കൈകാര്യം ചെയ്യാമെന്ന് ഞാൻ മനസ്സിലാക്കുന്നു
