## എജന്റിക് ആർക്കിടെക്ചറും ഓർക്കസ്ട്രേഷനും

പരീക്ഷയിലെ ഏറ്റവും വലുതും ഏറ്റവും ബുദ്ധിമുട്ടുള്ളതുമായ ഡൊമെയ്ൻ ആണിത് (ചോദ്യങ്ങളുടെ 27%, ഏകദേശം 16 എണ്ണം). ഓരോ പ്രോംപ്റ്റിനും ഒന്നൊന്നായി ഉത്തരം നൽകുക എന്നതിനപ്പുറം, Claude സ്വയം പ്രവർത്തിക്കാൻ അനുവദിക്കുന്നതിൽ ഉൾപ്പെട്ട എല്ലാ കാര്യങ്ങളും ഈ ഡൊമെയ്ൻ ഉൾക്കൊള്ളുന്നു. അതായത്: agentic loop ശരിയായി നിയന്ത്രിക്കുക (ശരിയായ `stop_reason` നോക്കി മാത്രം നിർത്തുക — ആവർത്തനങ്ങളുടെ എണ്ണം നോക്കിയോ ദുർബലമായ ടെക്സ്റ്റ് പാഴ്‌സിങ് വഴിയോ അല്ല), ഒരു coordinator ജോലി വിഭജിക്കുകയും subagent-കൾ അത് നിർവഹിക്കുകയും ചെയ്യുന്ന multi-agent സിസ്റ്റങ്ങൾ രൂപകൽപ്പന ചെയ്യുക, മൃദുവായ നിർദേശം (ഒരു system prompt) എപ്പോൾ മതിയാകില്ല എന്ന് തിരിച്ചറിഞ്ഞ് പകരം കർശനമായ, പ്രോഗ്രാം വഴിയുള്ള നിർബന്ധം (hooks, തടയുന്ന മുൻവ്യവസ്ഥകൾ) ഉപയോഗിക്കുക.

ഈ ഡൊമെയ്ൻ ബുദ്ധിമുട്ടുള്ളതാകുന്നത് ഇത് കൈകാര്യം ചെയ്യുന്ന പരാജയങ്ങൾ സൂക്ഷ്മമായതുകൊണ്ടാണ്: ഓരോ subagent-ഉം "വിജയകരമായി" പൂർത്തിയാക്കിയതിനാൽ സിസ്റ്റം ശരിയായി പ്രവർത്തിക്കുന്നതായി തോന്നാം — എന്നിട്ടും ഫലം അപൂർണമോ തെറ്റോ ആകാം, കാരണം യഥാർഥ കാരണം അതിനും മുകളിലാണ്: ജോലി എങ്ങനെ വിഭജിച്ചു എന്നതിലോ context എങ്ങനെ കൈമാറി എന്നതിലോ. പ്രൊഡക്ഷനിൽ നിന്നുള്ള തെളിവുകൾ (ലോഗുകൾ, പരാജയ നിരക്കുകൾ) നൽകി പരാജയത്തിന്റെ യഥാർഥ ഉറവിടം കണ്ടെത്താൻ ആവശ്യപ്പെടുന്ന സാഹചര്യ ചോദ്യങ്ങൾ പ്രതീക്ഷിക്കുക: loop നിയന്ത്രണം, task decomposition, ഏജന്റുകൾക്കിടയിലെ context isolation, അല്ലെങ്കിൽ prompting-ഉം enforcement-ഉം തമ്മിലുള്ള തിരഞ്ഞെടുപ്പ്.
