## MCP ക്രമീകരണം — Project vs. Personal

MCP സെർവറുകൾ പതിവായി ഉപയോഗിക്കാൻ തുടങ്ങിയാൽ ഒരു സ്വാഭാവിക ചോദ്യം വരും: ഏതൊക്കെ സെർവറുകളുമായി ബന്ധപ്പെടണം എന്ന് യഥാർഥത്തിൽ എവിടെയാണ് പ്രഖ്യാപിക്കുന്നത്, ആ പ്രഖ്യാപനം നിങ്ങൾക്ക് വ്യക്തിപരമായോ അതോ മുഴുവൻ ടീമിനുമോ ഉള്ളതാണ്? ക്രമീകരണം പങ്കിടേണ്ടതാണോ സ്വകാര്യമാണോ എന്നതിനെ ആശ്രയിച്ചിരിക്കും ഉത്തരം, Claude Code-ന്റെ ഉപകരണങ്ങൾ അത് വയ്ക്കാൻ രണ്ട് വ്യത്യസ്ത സ്ഥലങ്ങൾ നൽകുന്നു.

### രണ്ട് ക്രമീകരണ സ്ഥലങ്ങൾ

**`.mcp.json`**, പ്രോജക്ട് ഫോൾഡറിനുള്ളിൽ തന്നെ വയ്ക്കുന്നത്, കോഡ്ബേസിന്റെ ബാക്കി ഭാഗത്തിനൊപ്പം version control-ൽ ചേർക്കാൻ ഉദ്ദേശിച്ചുള്ളതാണ്. ഇത് git-ൽ ഉള്ളതിനാൽ, റെപ്പോസിറ്ററി clone ചെയ്യുന്ന എല്ലാവർക്കും കൃത്യമായി അതേ MCP സെർവറുകൾ സ്വയമേവ ക്രമീകരിച്ച് ലഭിക്കുന്നു — ആരും സ്വയം എന്തെങ്കിലും സജ്ജീകരിക്കാൻ ഓർക്കേണ്ടതില്ല. *മുഴുവൻ ടീമിനും* വേണ്ട ഉപകരണങ്ങളുടെ ശരിയായ ഇടമാണിത്: പങ്കിട്ട ഒരു ആന്തരിക API wrapper, ഒരു കമ്പനി ഡാറ്റാബേസ് കണക്ടർ, ഒരു ടിക്കറ്റിങ് സിസ്റ്റം integration.

**`~/.claude.json`**, ഡെവലപ്പറുടെ home ഫോൾഡറിൽ വയ്ക്കുന്നത്, ആ ഒരു യന്ത്രത്തിനും ആ ഒരു ഡെവലപ്പർക്കും മാത്രമുള്ളതാണ്. ഇത് ഒരിക്കലും git-ൽ ചേർക്കപ്പെടുന്നില്ല, സഹപ്രവർത്തകർ ഒരിക്കലും കാണുന്നുമില്ല. വ്യക്തിപരമോ പരീക്ഷണാത്മകമോ ആയ ഉപകരണങ്ങളുടെ ശരിയായ ഇടമാണിത് — ഒരുപക്ഷേ ടീമിന് നിർദേശിക്കും മുൻപ് ഒരു പുതിയ MCP സെർവർ പരീക്ഷിക്കുകയാകാം, അല്ലെങ്കിൽ പങ്കിട്ട പ്രോജക്ട് ക്രമീകരണത്തിൽ ഒരു കാര്യവുമില്ലാത്ത ഒരു വ്യക്തിഗത ഉപകരണം (നിങ്ങളുടെ സ്വന്തം notes ആപ്പിലേക്കുള്ള ഒരു കണക്ടർ പോലെ) ഉണ്ടാകാം.

### പങ്കിട്ട ക്രമീകരണത്തിൽ നിന്ന് രഹസ്യങ്ങൾ മാറ്റിനിർത്തൽ

ഉൾക്കൊള്ളേണ്ട ഒരു സൂക്ഷ്മത: `.mcp.json` git വഴി പങ്കിടുന്നു, അതായത് അതിൽ നേരിട്ട് എഴുതുന്നതെന്തും മുഴുവൻ ടീമിനും (റെപ്പോ പ്രവേശനമുള്ള ആർക്കും, git ചരിത്രത്തിൽ ഉൾപ്പെടെ) കാണാം. ഒരു ക്രമീകരണ മൂല്യം ഒരു രഹസ്യമാകുന്ന നിമിഷം — ഒരു API ടോക്കൺ, ഒരു പാസ്‌വേഡ്, ഒരു സ്വകാര്യ കീ — അതൊരു പ്രശ്നമാണ്. പരിഹാരം environment variable പകരംവയ്ക്കലാണ്: ഫയലിൽ `"token": "sk-abc123..."` എന്ന് ഉറപ്പിച്ചെഴുതുന്നതിന് പകരം `"token": "${GITHUB_TOKEN}"` എന്ന് എഴുതുന്നു, ഓരോ ഡെവലപ്പറുടെയും സ്വന്തം പരിസ്ഥിതി യഥാർഥ മൂല്യം നൽകുന്നു. *ഏത്* വേരിയബിൾ ഉപയോഗിക്കണമെന്ന് വിവരിക്കുമ്പോഴും പങ്കിട്ട ഫയൽ രഹസ്യങ്ങളില്ലാതെ നിലനിൽക്കുന്നു — ക്രമീകരണത്തിന്റെ മാതൃക പങ്കിടുന്നു, സ്പർശനക്ഷമമായ മൂല്യം പങ്കിടുന്നില്ല.

> **🌍 യഥാർഥ ഉദാഹരണം:** അഞ്ചംഗ എൻജിനീയറിങ് ടീം അവരുടെ monorepo-യുടെ റൂട്ടിൽ ഒരു പങ്കിട്ട `.mcp.json` സജ്ജീകരിക്കുന്നു, അത് ഒരു ആന്തരിക deployment-status MCP സെർവറും ഒരു GitHub MCP സെർവറും ബന്ധിപ്പിക്കുന്നു, `"token": "${GITHUB_TOKEN}"` ഉപയോഗിച്ച് — അങ്ങനെ പങ്കിട്ട ഒരു ടോക്കൺ റെപ്പോയിൽ ചേർക്കുന്നതിന് പകരം ഓരോ എൻജിനീയറുടെയും സ്വന്തം വ്യക്തിഗത പ്രവേശന ടോക്കൺ പ്രാദേശികമായി ഉപയോഗിക്കപ്പെടുന്നു. ഒരു എൻജിനീയർ കൂടാതെ സ്വന്തം ലാപ്ടോപ്പിൽ ഒരു `~/.claude.json` എൻട്രി ചേർക്കുന്നു — സ്വന്തം കലണ്ടർ സംഗ്രഹിക്കുന്ന ഒരു പരീക്ഷണാത്മക MCP സെർവറിന് വേണ്ടി — അയാൾക്ക് വ്യക്തിപരമായി ഉപകാരപ്രദം, പക്ഷേ ബാക്കി ടീമിനെ ബുദ്ധിമുട്ടിക്കാനോ അവർക്ക് വെളിപ്പെടുത്താനോ ഒരു കാരണവുമില്ല.

### രണ്ട് ക്രമീകരണ സ്ഥലങ്ങളുടെ താരതമ്യം

| ക്രമീകരണ സ്ഥലം | ആര് കാണുന്നു | Version control-ൽ ഉണ്ടോ? | എന്തിന് ഉപയോഗിക്കണം |
|---|---|---|---|
| `.mcp.json` (പ്രോജക്ട് ഫോൾഡർ) | ടീമിലെ എല്ലാവരും | ഉവ്വ് — git വഴി പങ്കിടുന്നു | എല്ലാവർക്കും വേണ്ട ടീം ഉപകരണങ്ങൾ |
| `~/.claude.json` (home ഫോൾഡർ) | ആ ഡെവലപ്പർ മാത്രം | ഇല്ല — പ്രാദേശികം മാത്രം | വ്യക്തിപരമോ പരീക്ഷണാത്മകമോ ആയ ഉപകരണങ്ങൾ |

> **💡 നുറുങ്ങ്:** ഒരു ക്രമീകരണ മൂല്യം സ്പർശനക്ഷമമായി കണക്കാക്കാവുന്നതാണെങ്കിൽ (ടോക്കണുകൾ, കീകൾ, ക്രെഡൻഷ്യലുകൾ), "ഇത് commit ചെയ്യാമോ?" എന്ന് ചോദിക്കുന്നതിന് പകരം സ്ഥിരസ്ഥിതിയായി `${VARIABLE_NAME}` പകരംവയ്ക്കൽ ഉപയോഗിക്കുക — മൂല്യം രഹസ്യമല്ലാത്തപ്പോൾ അതിന് ഒരു ചെലവുമില്ല, രഹസ്യമാകുമ്പോൾ അത് ഒരു അബദ്ധത്തിലുള്ള ചോർച്ച തടയുന്നു.
