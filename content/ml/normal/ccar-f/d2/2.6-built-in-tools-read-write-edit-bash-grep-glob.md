## ബിൽറ്റ്-ഇൻ ടൂളുകൾ — Read, Write, Edit, Bash, Grep, Glob

പ്രത്യേക MCP സെർവറുകൾക്ക് പുറമേ, ഒരു പ്രാദേശിക കോഡ്ബേസുമായി നേരിട്ട് പ്രവർത്തിക്കാൻ ചെറിയൊരു കൂട്ടം ബിൽറ്റ്-ഇൻ ടൂളുകളുമായാണ് Claude Code വരുന്നത്. ഇവ അസാധാരണമല്ല — ഒരു ഡെവലപ്പർ ദിവസവും കൈകൊണ്ട് ചെയ്യുന്ന കാര്യങ്ങളോട് അവ അടുത്തുനിൽക്കുന്നു — പക്ഷേ ഓരോന്നും എപ്പോൾ ഉപയോഗിക്കണമെന്നും (അവ പരസ്പരം എങ്ങനെ ബന്ധപ്പെട്ടിരിക്കുന്നു എന്നും) കൃത്യമായി അറിയുന്നതാണ് കാര്യക്ഷമമായ ടൂൾ ഉപയോഗത്തെ പാഴായതോ അപകടകരമോ ആയ ടൂൾ ഉപയോഗത്തിൽ നിന്ന് വേർതിരിക്കുന്നത്.

### ഓരോ ടൂളും വിശദമായി

- **`Read`** ഒരു ഫയലിന്റെ മുഴുവൻ ഉള്ളടക്കവും ലോഡ് ചെയ്യുന്നു. ഒരു ഫയലിലുള്ളതെല്ലാം — അതിന്റെ ഘടന, മുഴുവൻ ലോജിക്, അല്ലെങ്കിൽ ഇതുവരെ നോക്കാത്ത ഉള്ളടക്കം — യഥാർഥത്തിൽ കാണേണ്ടിവരുമ്പോൾ ഇത് ഉപയോഗിക്കുക. മിക്ക ഫയൽ പ്രവർത്തനങ്ങൾക്കും മുൻപുള്ള ആരംഭ ബിന്ദുവാണിത്.
- **`Write`** തീർത്തും പുതിയ ഒരു ഫയൽ സൃഷ്ടിക്കുന്നു, അല്ലെങ്കിൽ നിലവിലുള്ള ഒന്ന് പൂർണമായി മാറ്റിസ്ഥാപിക്കുന്നു. ഇതുവരെ ഒരു ഫയലില്ലാത്തപ്പോൾ, അല്ലെങ്കിൽ ചെറിയ തിരുത്തലുകളുടെ ഒരു പരമ്പരയെക്കാൾ പൂർണമായ പുനർലേഖനം വ്യക്തമാകുന്നത്ര വിപുലമായ മാറ്റമാകുമ്പോൾ ഇതാണ് ശരിയായ ടൂൾ.
- **`Edit`** ഒരു ഫയലിന്റെ ഒരു നിർദിഷ്ട ഭാഗത്ത് മാത്രം ലക്ഷ്യമിട്ട മാറ്റം വരുത്തുന്നു, ബാക്കി തൊടാതെ. ഒരു ഭാഗം മാത്രം മാറ്റേണ്ടപ്പോഴെല്ലാം `Write`-നെക്കാൾ ഇത് അഭികാമ്യമാണ്, കാരണം ഇത് കൂടുതൽ കൃത്യവും ബന്ധമില്ലാത്ത ഉള്ളടക്കം അബദ്ധത്തിൽ നഷ്ടപ്പെടാനുള്ള സാധ്യത കുറഞ്ഞതുമാണ്. പ്രധാന നിബന്ധന: `Edit` പൊരുത്തപ്പെടുത്തുന്ന ടെക്സ്റ്റ് ഫയലിൽ അദ്വിതീയമായിരിക്കണം — ആ പൊരുത്തം അദ്വിതീയമല്ലെങ്കിൽ (അല്ലെങ്കിൽ കണ്ടെത്തിയില്ലെങ്കിൽ) തിരുത്തൽ പരാജയപ്പെടും, പകരം വഴി ആദ്യം ഫയൽ `Read` ചെയ്ത് പിന്നെ ശരിയാക്കിയ പൂർണ രൂപം `Write` ചെയ്യുകയാണ്.
- **`Bash`** ടെർമിനൽ/ഷെൽ കമാൻഡുകൾ പ്രവർത്തിപ്പിക്കുന്നു — സ്ക്രിപ്റ്റുകൾ യഥാർഥത്തിൽ നടത്താനും, ഒരു ടെസ്റ്റ് സ്യൂട്ട് പ്രവർത്തിപ്പിക്കാനും, ഒരു build ടൂൾ വിളിക്കാനും ഇതാണ് വഴി. "ടെക്സ്റ്റ് തിരുത്തൽ" എന്നതിനും compile ചെയ്യുകയോ ടെസ്റ്റ് ചെയ്യുകയോ പോലുള്ള "കാര്യങ്ങൾ ചെയ്യൽ" എന്നതിനും ഇടയിലുള്ള പാലമാണിത്.
- **`Grep`** ഒരു ടെക്സ്റ്റ് മാതൃകയ്ക്കായി ഫയൽ *ഉള്ളടക്കം* തിരയുന്നു. എന്ത് ടെക്സ്റ്റ് തിരയുന്നു എന്ന് ഏകദേശം അറിയാമെങ്കിലും അത് ഏത് ഫയലിലാണെന്ന് അറിയാത്തപ്പോൾ ഇത് ഉപയോഗിക്കുക — ഉദാഹരണത്തിന്, ഒരു ഫംഗ്ഷന്റെ എല്ലാ വിളി സ്ഥലങ്ങളും, അല്ലെങ്കിൽ ഒരു പ്രത്യേക പിഴവ് സന്ദേശം വരുന്ന എല്ലാ ഇടങ്ങളും.
- **`Glob`** ഉള്ളടക്കം കൊണ്ടല്ല, *പേര്* മാതൃക കൊണ്ട് ഫയലുകൾ കണ്ടെത്തുന്നു. വേണ്ട ഫയൽ പേരിന്റെ രൂപം അറിയാമെങ്കിലും (എല്ലാ ടെസ്റ്റ് ഫയലുകൾക്കും `**/*.test.tsx`, എല്ലാ config ഫയലുകൾക്കും `**/*.config.js`) അവയിലൊന്നും ഇതുവരെ നോക്കിയിട്ടില്ലാത്തപ്പോൾ ഇത് ഉപയോഗിക്കുക.

### ലളിതമായ ഒരു തീരുമാന വഴി

ഇങ്ങനെ ചിന്തിക്കുന്നത് ഉപകാരപ്രദമാണ്: "എന്ത് ടെക്സ്റ്റ് തിരയണമെന്ന് അറിയാമോ, അതോ ഏത് ഫയൽ പേര് മാതൃക തിരയണമെന്നോ?" → `Grep` vs `Glob`. "ഒരു മുഴുവൻ ഫയലും കാണണോ, അതിന്റെ ഒരു ഭാഗം മാറ്റണോ, അതോ മുഴുവനും മാറ്റണോ?" → `Read` vs `Edit` vs `Write`. "ടെക്സ്റ്റ് വായിക്കുകയോ മാറ്റുകയോ ചെയ്യുന്നതിനപ്പുറം എന്തെങ്കിലും യഥാർഥത്തിൽ നടത്തേണ്ടതുണ്ടോ?" → `Bash`.

> **🌍 യഥാർഥ ഉദാഹരണം:** ഒരു വലിയ റെപ്പോസിറ്ററിയിലുടനീളം `formatDate` എന്ന helper ഫംഗ്ഷന്റെ പേര് `formatDateTime` എന്നാക്കാനും അതിലെ ഒരു തെറ്റായ വരി പുതുക്കാനും ഒരു coding agent-നോട് ആവശ്യപ്പെടുന്നു. `formatDate` പരാമർശിക്കുന്ന എല്ലാ ഫയലുകളും കണ്ടെത്താൻ അത് ആദ്യം `Grep` ഉപയോഗിക്കുന്നു (ഉള്ളടക്ക തിരയൽ), ഫംഗ്ഷന്റെ നിർവചന ഫയൽ `Read` കൊണ്ട് സ്ഥിരീകരിക്കുന്നു, ചുറ്റുമുള്ള പൊരുത്തം അദ്വിതീയമായതിനാൽ `Edit` കൊണ്ട് കൃത്യമായ ഒരു വരി തിരുത്തൽ നടത്തുന്നു, പിന്നെ ഒന്നും തകർന്നിട്ടില്ലെന്ന് ഉറപ്പാക്കാൻ ടെസ്റ്റ് സ്യൂട്ട് പ്രവർത്തിപ്പിക്കാൻ `Bash` ഉപയോഗിക്കുന്നു. ഒരു ഫയലിനും പൂർണ പുനർലേഖനം വേണ്ടിവരാത്തതിനാൽ `Write` ഒരിക്കലും വേണ്ടിവന്നില്ല, ഒരു ഫയൽ പേര് മാതൃകയല്ല ഒരു symbol ആണ് തിരഞ്ഞതെന്നതിനാൽ `Glob`-ഉം വേണ്ടിവന്നില്ല.

### ഫയൽ തിരുത്തൽ ടൂളുകൾക്കിടയിൽ തിരഞ്ഞെടുക്കൽ

| ടൂൾ | എന്ത് ചെയ്യുന്നു | എപ്പോൾ ഉപയോഗിക്കണം |
|---|---|---|
| `Read` | മുഴുവൻ ഫയൽ ഉള്ളടക്കവും വായിക്കുന്നു | മുഴുവൻ ഫയലും കാണേണ്ടിവരുമ്പോൾ |
| `Write` | ഒരു ഫയൽ സൃഷ്ടിക്കുകയോ മാറ്റിസ്ഥാപിക്കുകയോ ചെയ്യുന്നു | പുതിയ ഫയലുകൾ ഉണ്ടാക്കുമ്പോഴോ പൂർണ പുനർലേഖനം നടത്തുമ്പോഴോ |
| `Edit` | ഒരു ഫയലിന്റെ നിർദിഷ്ട ഭാഗത്ത് ലക്ഷ്യമിട്ട മാറ്റങ്ങൾ വരുത്തുന്നു | ഒരു ഭാഗം മാത്രം മാറ്റുമ്പോൾ; അദ്വിതീയ പൊരുത്തമില്ലെങ്കിൽ Read + Write-ലേക്ക് മാറുന്നു |
| `Bash` | ടെർമിനൽ/ഷെൽ കമാൻഡുകൾ പ്രവർത്തിപ്പിക്കുന്നു | സ്ക്രിപ്റ്റുകൾ, ടെസ്റ്റുകൾ, build കമാൻഡുകൾ നടത്തുമ്പോൾ |
| `Grep` | ടെക്സ്റ്റ് മാതൃകകൾക്കായി ഫയൽ ഉള്ളടക്കം തിരയുന്നു | ഒരു ഫംഗ്ഷന്റെ എല്ലാ വിളി സ്ഥലങ്ങളും, പിഴവ് സന്ദേശങ്ങളും കണ്ടെത്തുമ്പോൾ |
| `Glob` | ഒരു പേര് മാതൃകയുമായി പൊരുത്തപ്പെടുന്ന ഫയലുകൾ കണ്ടെത്തുന്നു | എല്ലാ ടെസ്റ്റ് ഫയലുകളും, എല്ലാ config ഫയലുകളും കണ്ടെത്തുമ്പോൾ |

> **⚠️ ശ്രദ്ധിക്കുക:** ആദ്യം `Read` ചെയ്യാത്ത ഒരു ഫയലിൽ `Write` ഉപയോഗിക്കുന്നത്, അവിടെയുണ്ടെന്ന് അറിയാത്ത നിലവിലുള്ള ഉള്ളടക്കം നിശ്ശബ്ദമായി നഷ്ടപ്പെടുത്താനുള്ള അപകടമുണ്ടാക്കുന്നു. നിലവിലുള്ള ഒരു ഫയലിൽ സുരക്ഷിതമായ സ്ഥിരസ്ഥിതി ആദ്യം `Read`, പിന്നെ `Edit` (അല്ലെങ്കിൽ അതിൽ ഇപ്പോൾ എന്താണുള്ളതെന്ന് യഥാർഥത്തിൽ കണ്ടശേഷം മാത്രം പൂർണമായ ഒരു `Write`) എന്നതാണ്.
