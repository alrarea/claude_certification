## വിഭജന രീതികൾ

ഒരു multi-agent സിസ്റ്റത്തിന്റെ topology-യോ ഒരു workflow-ന്റെ ഘട്ടങ്ങളോ രൂപകൽപ്പന ചെയ്യും മുൻപ്, അതിനു മുൻപുള്ള ഒരു ചോദ്യത്തിന് ഉത്തരം വേണം: ഏത് അക്ഷത്തിലാണ് നിങ്ങൾ യഥാർഥത്തിൽ പ്രശ്നം വിഭജിക്കുന്നത്? ഒരൊറ്റ agent-ന് (അല്ലെങ്കിൽ ഒരൊറ്റ workflow ഘട്ടത്തിന്) ഓരോ ഭാഗവും വിശ്വസനീയമായി ചെയ്യാൻ കഴിയുന്നത്ര ചെറുതായി ഒരു വലിയ ജോലിയെ മുറിക്കുന്നതാണ് വിഭജനം. ഇത് തെറ്റിയാൽ — തെറ്റായ അക്ഷത്തിൽ വിഭജിച്ചാൽ, അല്ലെങ്കിൽ വേണ്ടത്ര സൂക്ഷ്മമായി വിഭജിക്കാതിരുന്നാൽ — മറ്റെല്ലാ വിധത്തിലും നന്നായി രൂപകൽപ്പന ചെയ്തതായി തോന്നുന്ന സിസ്റ്റങ്ങളിൽ ഫലം വിട്ടുപോകുന്നതിന്റെയോ തെറ്റാകുന്നതിന്റെയോ ഏറ്റവും സാധാരണമായ ഒറ്റ മൂലകാരണം അതാണ്.

### പ്രശ്നം മുറിക്കാനുള്ള മൂന്ന് വഴികൾ

| രീതി | എങ്ങനെ പ്രവർത്തിക്കുന്നു | എപ്പോൾ ഏറ്റവും ഇണങ്ങുന്നു |
|---|---|---|
| **Functional decomposition** | *ഓരോ ഭാഗവും എന്ത് ചെയ്യുന്നു* എന്നതനുസരിച്ച് വിഭജിക്കുക — ഒരു agent ഗവേഷണം ചെയ്യുന്നു, ഒന്ന് എഴുതുന്നു, ഒന്ന് review ചെയ്യുന്നു | ജോലിക്ക് പരസ്പരം ഇടകലരാത്ത, സ്വാഭാവികമായി വ്യത്യസ്തമായ ഘട്ടങ്ങളോ വൈദഗ്ധ്യ തരങ്ങളോ ഉണ്ട് |
| **Data decomposition** | *പ്രോസസ്സ് ചെയ്യുന്ന ഡാറ്റ* അനുസരിച്ച് വിഭജിക്കുക — ഓരോ രേഖയ്ക്കും, ഓരോ റെക്കോർഡിനും, ഓരോ ഭാഗത്തിനും ഒരു agent (അല്ലെങ്കിൽ ഒരു വിളി) | പരസ്പരം സ്വതന്ത്രമായ ഒട്ടേറെ ഡാറ്റാ ഘടകങ്ങളിൽ അതേ പ്രവർത്തനം ആവർത്തിക്കണം |
| **Domain decomposition** | *ബിസിനസ് മേഖല* അനുസരിച്ച് വിഭജിക്കുക — ഒരു legal agent, ഒരു finance agent, ഒരു HR agent | പ്രശ്നത്തിന്റെ വ്യത്യസ്ത ഭാഗങ്ങൾക്ക് വ്യത്യസ്ത വിഷയ വൈദഗ്ധ്യമോ നയ പരിജ്ഞാനമോ വേണം |

ഈ അക്ഷങ്ങൾ പരസ്പരം ഒഴിവാക്കുന്നവയല്ല, യഥാർഥ സിസ്റ്റങ്ങൾ പലപ്പോഴും അവയെ കൂട്ടിച്ചേർക്കുന്നു — ഉദാഹരണത്തിന്, ഒരു രേഖാ പ്രോസസ്സിങ് pipeline data decomposition (ഓരോ രേഖയ്ക്കും ഒരു pass) ഉപയോഗിക്കുകയും ഓരോ pass-നുള്ളിലും functional decomposition (ഒരു extraction ഘട്ടം, പിന്നെ ഒരു validation ഘട്ടം, പിന്നെ ഒരു സംഗ്രഹ ഘട്ടം) ഉപയോഗിക്കുകയും ചെയ്യാം.

### മോശം വിഭജനം സിസ്റ്റങ്ങളെ തകർക്കുന്നത് എന്തുകൊണ്ട്

ഒരു ജോലി തെറ്റായി വിഭജിക്കപ്പെടുമ്പോൾ, രണ്ട് പരാജയ മാതൃകകളിൽ ഒന്ന് പ്രത്യക്ഷപ്പെടാറുണ്ട്:

- **ഭാഗങ്ങൾ വളരെ വലുത്** — ഒരൊറ്റ ഘട്ടത്തിൽ ഒരൊറ്റ agent-നോട് ഇപ്പോഴും വളരെയധികം ചെയ്യാൻ ആവശ്യപ്പെടുന്നു, അതിനാൽ അത് ആവശ്യങ്ങൾ നിശ്ശബ്ദമായി ഒഴിവാക്കുകയോ, ജോലി പാതി മാത്രം പൂർത്തിയാക്കുകയോ, പൂർണമെന്ന് തോന്നിക്കുന്ന പക്ഷേ പ്രധാനപ്പെട്ട എന്തെങ്കിലും വിട്ടുപോയ ഒരു ഉത്തരം നൽകുകയോ ചെയ്യുന്നു. പരീക്ഷാ സാമഗ്രികൾ പ്രത്യേകം മുന്നറിയിപ്പ് നൽകുന്ന "ഫലം വിട്ടുപോകുന്ന" പരാജയം ഇതാണ്.
- **തെറ്റായ അക്ഷത്തിൽ മുറിച്ച ഭാഗങ്ങൾ** — ഉദാഹരണത്തിന്, യഥാർഥ സങ്കീർണത functional ആയിരിക്കെ (ഓരോ രേഖയ്ക്കും അതേ അഞ്ച് ഘട്ട വിശകലനം വേണം) ഡാറ്റ അനുസരിച്ച് (ഓരോ രേഖയ്ക്കും) വിഭജിച്ചാൽ, ഓരോ രേഖയ്ക്കും അഞ്ച് വേറിട്ട agent-കൾ ഉണ്ടാകും, പക്ഷേ ഓരോ ഘട്ടത്തിലെയും ഗുണനിലവാരത്തിന് വ്യക്തമായ ഉടമസ്ഥതയുണ്ടാകില്ല; അല്ലെങ്കിൽ തിരിച്ച്: സങ്കീർണതയുടെ യഥാർഥ കാരണം മേഖലാ വൈദഗ്ധ്യമായിരിക്കെ function അനുസരിച്ച് വിഭജിച്ചാൽ, ഒരിക്കലും context നൽകിയിട്ടില്ലാത്ത നിയമപരവും സാമ്പത്തികവുമായ സൂക്ഷ്മതകൾ എങ്ങനെയോ അറിഞ്ഞിരിക്കേണ്ട ഒരു "writer" agent ഉണ്ടാകും.

ശരിയായ വിഭജന അക്ഷം എന്നത് *യഥാർഥ സങ്കീർണത* എവിടെയാണോ അതിനോട് ഇണങ്ങുന്നതാണ് — ഒരു ചിത്രമായി വരയ്ക്കാൻ ഏറ്റവും എളുപ്പമുള്ളതല്ല.

> **🌍️ യഥാർഥ ഉദാഹരണം:** ഒരു ഇൻഷുറൻസ് കമ്പനിക്ക് 50,000 ക്ലെയിം രേഖകളുടെ കുടിശ്ശിക പ്രോസസ്സ് ചെയ്യണം, ഓരോന്നിനും അതേ വിശകലനം വേണം: പോളിസി വിവരങ്ങൾ എടുക്കുക, തട്ടിപ്പിന്റെ സൂചനകൾ പരിശോധിക്കുക, ഒരു സെറ്റിൽമെന്റ് ശുപാർശ തയ്യാറാക്കുക. *ഡാറ്റ* അനുസരിച്ച് മാത്രം വിഭജിച്ച് (ഓരോ രേഖയ്ക്കും ഒരു agent) *functional* വിഭജനം ഒഴിവാക്കുന്ന ഒരു ടീമിന് ഓരോ രേഖയ്ക്കും അമിത വലുപ്പമുള്ള ഒരൊറ്റ agent ലഭിക്കുന്നു — അത് ഒറ്റ pass-ൽ എടുക്കാനും തട്ടിപ്പ് വിലയിരുത്താനും ശുപാർശ എഴുതാനും ശ്രമിക്കുന്നു — ഇതിനകം നീണ്ട ഒരൊറ്റ prompt-നുള്ളിൽ മൂന്നിൽ രണ്ടാം ഘട്ടമായി കുഴിച്ചിട്ടതിനാൽ തട്ടിപ്പ് പരിശോധനയ്ക്ക് വേണ്ടത്ര ശ്രദ്ധ കിട്ടുന്നില്ല. Data decomposition (ഓരോ രേഖയ്ക്കും ഒരു pass) functional decomposition-മായി (പ്രത്യേകമായ ഒരു extraction ഘട്ടം, പിന്നെ പ്രത്യേകമായ ഒരു തട്ടിപ്പ് പരിശോധനാ ഘട്ടം, പിന്നെ ഒരു എഴുത്ത് ഘട്ടം) ചേർത്ത് പുനഃക്രമീകരിക്കുന്നത് ഫലം വിട്ടുപോകുന്ന പ്രശ്നം പരിഹരിക്കുന്നു, കാരണം ഓരോ ഘട്ടവും ഇപ്പോൾ സമഗ്രമായി ചെയ്യാൻ കഴിയുന്നത്ര ചെറുതാണ്.

> **📝️ പരീക്ഷാ ശ്രദ്ധ:** മറ്റെല്ലാ വിധത്തിലും യുക്തിസഹമെന്ന് തോന്നുന്ന ഒരു architecture-ൽ നിന്ന് "ചിലപ്പോൾ അപൂർണമായ" അല്ലെങ്കിൽ "ഇടയ്ക്കിടെ ആവശ്യങ്ങൾ വിട്ടുപോകുന്ന" ഫലത്തെക്കുറിച്ച് ഒരു സാഹചര്യം പറയുമ്പോൾ, വിഭജനമാണ് പ്രധാന സംശയം — പ്രത്യേകിച്ച്, ഇപ്പോഴും വളരെ വലിയ ഭാഗങ്ങൾ, അല്ലെങ്കിൽ സങ്കീർണത യഥാർഥത്തിൽ എവിടെയാണോ അതിന് തെറ്റായ അക്ഷത്തിൽ മുറിച്ചവ.
