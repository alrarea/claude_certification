# സൊല്യൂഷൻ ഡിസൈനും ആർക്കിടെക്ചറും (In-Depth)

പരീക്ഷയുടെ 17% (ഏകദേശം 11 ചോദ്യങ്ങൾ) വരുന്ന Solution Design & Architecture ആണ് എല്ലാറ്റിന്റെയും തുടക്കം: സിസ്റ്റങ്ങൾ സംയോജിപ്പിക്കാനോ ഗുണനിലവാരം വിലയിരുത്താനോ ഗവേണൻസ് കൈകാര്യം ചെയ്യാനോ കഴിയുന്നതിനു മുൻപ്, *എന്ത് നിർമിക്കണം* എന്ന് ആദ്യം തീരുമാനിക്കണം. "ഉപഭോക്തൃ സേവനം മെച്ചപ്പെടുത്താൻ ഞങ്ങൾക്ക് AI ഉപയോഗിക്കണം" എന്നതുപോലുള്ള അവ്യക്തമായ ഒരു ബിസിനസ് ആവശ്യം എടുത്ത്, അതിനെ വ്യക്തവും ന്യായീകരിക്കാവുന്നതുമായ ഒരു architecture ആക്കി മാറ്റാൻ നിങ്ങൾക്ക് കഴിയുമോ എന്നാണ് ഈ ഡൊമെയ്ൻ പരിശോധിക്കുന്നത്: ഏതൊക്കെ ഭാഗങ്ങളിൽ Claude ഉപയോഗിക്കണം, ഘടകങ്ങൾ എങ്ങനെ വിഭജിക്കണം, agent-കൾ (ഉണ്ടെങ്കിൽ) എങ്ങനെ ക്രമീകരിക്കണം, മൊത്തത്തിൽ ഇത് എങ്ങനെ തുടക്കം മുതൽ ഒടുക്കം വരെ മൂല്യം സൃഷ്ടിക്കുന്നു എന്നിവ.

ഒരു ബിസിനസ് പ്രശ്നം നൽകി ശരിയായ architectural pattern തിരഞ്ഞെടുക്കാൻ ആവശ്യപ്പെടുന്ന, ഒരു use case-നെ ബിസിനസ് മൂല്യവുമായി ബന്ധിപ്പിക്കാൻ പറയുന്ന, സങ്കീർണമായ ഒരു ജോലി പല agent-കൾക്കോ ഘടകങ്ങൾക്കോ ഇടയിൽ വിഭജിക്കാൻ ആവശ്യപ്പെടുന്ന, മോഡൽ വിളി മാത്രം ഒറ്റയ്ക്ക് നോക്കാതെ input → processing → output → feedback loop എന്ന മുഴുവൻ ചക്രത്തെക്കുറിച്ചും ചിന്തിക്കാൻ പറയുന്ന സാഹചര്യ ചോദ്യങ്ങൾ പ്രതീക്ഷിക്കുക.

> **📝️ പരീക്ഷാ ശ്രദ്ധ:** ഈ ചോദ്യങ്ങൾക്ക് ഒറ്റയ്ക്ക് നോക്കിയാൽ ഒരൊറ്റ "സാങ്കേതികമായി ശരിയായ" ഉത്തരം ഉണ്ടാകാറില്ല — നിങ്ങളുടെ architecture തിരഞ്ഞെടുപ്പ് *പറഞ്ഞിരിക്കുന്ന* ബിസിനസ് പരിമിതികൾക്ക് (ചെലവ്, latency, ടീമിന്റെ വലുപ്പം, റിസ്ക് സഹിഷ്ണുത) ഇണങ്ങുന്നുണ്ടോ എന്നാണ് അവ പരിശോധിക്കുന്നത്.
