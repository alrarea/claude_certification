# Claude മോഡലുകൾ, Prompting, Context Engineering (In-Depth)

പരീക്ഷയുടെ 13% (ഏകദേശം 8 ചോദ്യങ്ങൾ) വരുന്ന ഈ ഡൊമെയ്ൻ, prompting അടിസ്ഥാനങ്ങൾ Foundations-ൽ നിന്ന് നിങ്ങൾക്ക് അറിയാമെന്ന് കരുതി *എൻജിനീയറിങ്* തീരുമാനങ്ങളിലേക്ക് കൂടുതൽ ആഴത്തിൽ പോകുന്നു: ഒരു ജോലിക്ക് ഏത് മോഡലാണ് യഥാർഥത്തിൽ ഇണങ്ങുന്നത്, prompt-കൾ വിശ്വസനീയവും പ്രവർത്തിപ്പിക്കാൻ വിലകുറഞ്ഞതുമാക്കാൻ എങ്ങനെ ഘടനപ്പെടുത്തണം, context window-യിൽ എല്ലാം കുത്തിനിറയ്ക്കുന്നതിനു പകരം അത് എങ്ങനെ ബോധപൂർവം കൈകാര്യം ചെയ്യണം.

ആവർത്തിക്കുന്ന ഒരു വിഷയം വിട്ടുവീഴ്ചകളാണ്: വേഗമുള്ള/വിലകുറഞ്ഞ മോഡലുകൾ vs. കൂടുതൽ ശേഷിയുള്ളവ, zero-shot vs. few-shot vs. chain-of-thought prompting, ഒപ്പം — വളരെ പതിവായി പരിശോധിക്കപ്പെടുന്ന — prompt caching, അവിടെ സ്ഥിരമായ ഉള്ളടക്കം ആദ്യവും മാറുന്ന ഉള്ളടക്കം അവസാനവും വെക്കുന്നത് ആവർത്തിക്കുന്ന prefix-കൾ വീണ്ടും ഉപയോഗിക്കാൻ അനുവദിച്ച് ചെലവും latency-യും കുറയ്ക്കുന്നു. Role, അതിരുകൾ, ഔട്ട്പുട്ട് രൂപം, guardrail-കൾ എന്നിവ വ്യക്തമായി സ്ഥാപിക്കുന്ന ഒരു system prompt രൂപകൽപ്പന ചെയ്യാനും നിങ്ങൾക്ക് കഴിയണം, കാരണം ആ ഘടന മറ്റെല്ലാ ഡൊമെയ്നുകളിലും പ്രത്യക്ഷപ്പെടുന്നു.

> **🔑️ പ്രധാന നിഗമനം:** ഈ ഡൊമെയ്നിൽ ഏറ്റവും പതിവായി പരിശോധിക്കപ്പെടുന്ന വ്യക്തമായ രീതികളിൽ ഒന്നാണ് prompt caching (സ്ഥിരമായ ഉള്ളടക്കം ആദ്യം, മാറുന്നത് അവസാനം) — ഇത് കൃത്യമായി അറിഞ്ഞിരിക്കുക.
