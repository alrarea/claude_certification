## 12 ഔദ്യോഗിക മാതൃകാ ചോദ്യങ്ങളും — വേഗ ഉത്തരസൂചിക

### സാഹചര്യം A: Customer Support Agent

- **Q1 (D1):** ഉത്തരം **A** — നിർണായകമായ ബിസിനസ് യുക്തിക്ക് (റീഫണ്ടിനു മുൻപ് ഐഡന്റിറ്റി പരിശോധന) prompt നിർദേശങ്ങളല്ല, programmatic enforcement വേണം.
- **Q2 (D2):** ഉത്തരം **B** — ആദ്യം ടൂൾ വിവരണങ്ങൾ വിപുലീകരിക്കുക; ടൂൾ തിരഞ്ഞെടുക്കൽ പിഴവുകളുടെ സ്ഥിരം മൂലകാരണം അവ്യക്തമായ വിവരണങ്ങളാണ്.
- **Q3 (D5):** ഉത്തരം **A** — വ്യക്തമായ കൈമാറ്റ മാനദണ്ഡങ്ങളും few-shot ഉദാഹരണങ്ങളും ചേർക്കുക; സ്വയം പറയുന്ന ആത്മവിശ്വാസവും വികാരവും വിശ്വസിക്കാനാകാത്ത ട്രിഗറുകളാണ്.

### സാഹചര്യം B: Code Generation with Claude Code

- **Q4 (D3):** ഉത്തരം **A** — repo-യിലെ `.claude/commands/` version control-ൽ വരുന്നു, ഓരോ ഡെവലപ്പറുമായും പങ്കിടുന്നു.
- **Q5 (D3):** ഉത്തരം **A** — വലുതും architecture-പരമായി അവ്യക്തവുമായ മാറ്റങ്ങൾക്ക് നിർവഹണത്തിനു മുൻപ് plan mode വേണം.
- **Q6 (D3):** ഉത്തരം **A** — glob മാതൃകകളുള്ള `.claude/rules/`, സ്ഥാനം നോക്കാതെ ഫയൽ തരം അനുസരിച്ച് രീതികൾ ബാധകമാക്കുന്നു.

### സാഹചര്യം C: Multi-Agent Research System

- **Q7 (D1):** ഉത്തരം **B** — അപൂർണമായ multi-agent ഫലത്തിന്റെ വേര്, coordinator-ന്റെ task decomposition വളരെ ഇടുങ്ങിയതായിരുന്നു എന്നതാണ്.
- **Q8 (D5):** ഉത്തരം **A** — പരാജയങ്ങൾ പൊതുവായ സന്ദേശമായല്ല, ഘടനാപരമായ പിഴവ് context ആയി (തരം, ചോദ്യം, ഭാഗിക ഫലങ്ങൾ, ബദലുകൾ) കൈമാറണം.
- **Q9 (D2):** ഉത്തരം **A** — സാധാരണ സാഹചര്യത്തിന് synthesis agent-ന് ഇടുങ്ങിയ പരിധിയുള്ള ഒരു `verify_fact` ടൂൾ നൽകുക; least privilege ജയിക്കുന്നു.

### സാഹചര്യം D: Claude Code for CI/CD

- **Q10 (D3):** ഉത്തരം **A** — pipeline-കളിൽ ഇടപെടലില്ലാത്ത Claude Code പ്രവർത്തനത്തിന് `-p` flag ഉപയോഗിക്കുക.
- **Q11 (D4):** ഉത്തരം **A** — രാത്രി റിപ്പോർട്ട് മാത്രം batch ചെയ്യുക; merge-നു മുൻപുള്ള പരിശോധനകൾ തടസ്സപ്പെടുത്തുന്നവയാണ്, അവയ്ക്ക് തത്സമയ വിളികൾ വേണം.
- **Q12 (D4):** ഉത്തരം **A** — ഒട്ടേറെ ഫയലുകളിലായി ശ്രദ്ധ ചിതറുന്നത് പരിഹരിക്കാൻ ഓരോ ഫയലിനുമുള്ള pass-കളും വേറിട്ട ഒരു integration pass-ഉം ആയി വിഭജിക്കുക.
