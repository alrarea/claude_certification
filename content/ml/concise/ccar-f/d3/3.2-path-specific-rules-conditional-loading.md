> **🔑️ പ്രധാന നിഗമനം:** `.claude/rules/`-ലെ path അടിസ്ഥാനമാക്കിയ നിയമങ്ങൾ frontmatter-ൽ glob മാതൃകകൾ ഉപയോഗിക്കുന്നു; അതുകൊണ്ട് പൊരുത്തപ്പെടുന്ന ഒരു ഫയൽ തിരുത്തുമ്പോൾ മാത്രമേ ആ നിയമം Claude-ന്റെ context-ലേക്ക് വരൂ — ബന്ധമില്ലാത്ത നിയമങ്ങൾ വഴിയിൽ നിൽക്കില്ല.

- നിയമ ഫയലുകൾ `.claude/rules/`-ൽ ഇരിക്കുന്നു, ഓരോന്നിനും frontmatter-ൽ glob മാതൃകകളുടെ ഒരു `paths:` ശ്രേണി ഉണ്ട് (ഉദാ: `["**/*.test.tsx", "**/*.spec.ts"]`).
- ആ മാതൃകകളിൽ ഒന്നിനോട് പൊരുത്തപ്പെടുന്ന ഫയലിൽ Claude ജോലി ചെയ്യുമ്പോൾ മാത്രമേ നിയമത്തിന്റെ ഉള്ളടക്കം context-ലേക്ക് വരൂ.
- ഉദ്ദേശ്യം: നിലവിലെ ഫയലുമായി ബന്ധമില്ലാത്ത നിയമങ്ങൾ കൊണ്ട് Claude-ന്റെ context നിറയാതിരിക്കുക (ഉദാ: ഒരു config ഫയൽ തിരുത്തുമ്പോൾ ടെസ്റ്റിങ് രീതികൾ ലോഡ് ചെയ്യേണ്ടതില്ല).
- **directory തല CLAUDE.md-നു പകരം ഇത് എപ്പോൾ തിരഞ്ഞെടുക്കണം:** പൊരുത്തപ്പെടുന്ന ഫയലുകൾ ഒരിടത്ത് ഒതുങ്ങാതെ പല ഫോൾഡറുകളിൽ ചിതറിക്കിടക്കുമ്പോൾ — directory തല CLAUDE.md-ന് ഒരു ഭൗതിക ഫോൾഡറിനെ മാത്രമേ ലക്ഷ്യമിടാനാകൂ, മരം മുഴുവനുമുള്ള ഒരു ഫയൽ *മാതൃക*യെ അല്ല.
- മാതൃകാ ഉപയോഗം: ഡസൻ കണക്കിന് ഫീച്ചർ ഫോൾഡറുകളിൽ ഒപ്പം കിടക്കുന്ന ടെസ്റ്റ് ഫയലുകൾ (`*.test.tsx`, `*.spec.ts`).
