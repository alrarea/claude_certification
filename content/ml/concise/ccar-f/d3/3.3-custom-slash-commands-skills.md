> **🔑️ പ്രധാന നിഗമനം:** slash commands-ഉം Skills-ഉം ആവർത്തിക്കുന്ന workflows-നെ ഒരു ചെറിയ ട്രിഗറിനു പിന്നിൽ പൊതിയുന്നു; സാധാരണ commands-ന് ഇല്ലാത്ത isolation-ഉം സുരക്ഷാ ക്രമീകരണവും Skills നൽകുന്നു.

- **Slash commands**: മുൻകൂട്ടി നിശ്ചയിച്ച ഒരു workflow പ്രവർത്തിപ്പിക്കുന്ന, സൂക്ഷിച്ചുവെച്ച prompt കുറുക്കുവഴികൾ (ഉദാ: `/project:review-pr`).
- **Skills**: സമാനമായ ആശയം, പക്ഷേ സ്വന്തം ഒറ്റപ്പെട്ട context-ൽ പ്രവർത്തിക്കുന്നു, കൂടുതൽ frontmatter ക്രമീകരണം പിന്തുണയ്ക്കുന്നു.
- **സ്ഥാനങ്ങൾ CLAUDE.md ശ്രേണിയെ പിന്തുടരുന്നു:**
  - `.claude/commands/` — project command, git വഴി പങ്കിടുന്നു, ടീമിലെ എല്ലാവർക്കും.
  - `~/.claude/commands/` — വ്യക്തിപരമായ command, നിങ്ങൾക്ക് മാത്രം.
  - `.claude/skills/` — project Skill, git വഴി പങ്കിടുന്നു.
  - `~/.claude/skills/` — വ്യക്തിപരമായ Skill, നിങ്ങൾക്ക് മാത്രം.
- **പ്രധാന SKILL.md frontmatter സാധ്യതകൾ:**
  - `context: fork` — ഒരു ഒറ്റപ്പെട്ട ഉപ-session-ൽ പ്രവർത്തിക്കുന്നു, അതിനാൽ നീണ്ട ഔട്ട്പുട്ട് പ്രധാന സംഭാഷണം നിറയ്ക്കില്ല.
  - `allowed-tools: [Read, Write]` — Skill-ന് ഏതൊക്കെ ടൂളുകൾ ഉപയോഗിക്കാമെന്ന് പരിമിതപ്പെടുത്തുന്നു, നാശകരമായ നടപടികൾ തടയുന്നു.
  - `argument-hint: "PR number"` — ആവശ്യമായ ഒരു പരാമീറ്റർ ഇല്ലാതെ വിളിച്ചാൽ അത് ചോദിക്കുന്നു.
- isolation-ഉം ടൂൾ പരിമിതികളും വേണമെങ്കിൽ സാധാരണ commands-നു പകരം Skills ഉപയോഗിക്കുക; ലളിതവും അപകടം കുറഞ്ഞതുമായ കുറുക്കുവഴികൾക്ക് commands മതി.
