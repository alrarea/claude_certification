> **🔑️ പ്രധാന നിഗമനം:** CI/CD-യിൽ Claude Code പ്രവർത്തിപ്പിക്കാൻ ഇടപെടൽ ആവശ്യമില്ലാത്ത, യന്ത്രത്തിന് വായിക്കാവുന്ന ഫ്ലാഗുകൾ വേണം; കോഡ് review എപ്പോഴും കോഡ് എഴുതിയ Claude അല്ലാതെ പുതിയൊരു സ്വതന്ത്ര Claude ചെയ്യണം.

- CI/CD pipeline-കൾ സ്വയമേവയുള്ളതും ആരും നോക്കിയിരിക്കാത്തതുമാണ് — മനുഷ്യന്റെ ഇൻപുട്ടിനായി കാത്തിരിക്കുന്ന ഏതൊരു ചോദ്യവും ജോലിയെ എന്നെന്നേക്കുമായി തൂക്കിയിടും.
- **`-p` / `--print`:** ഇടപെടലില്ലാത്ത മോഡ്; ഇൻപുട്ടിനായി കാത്തിരിക്കാതെ പ്രവർത്തിച്ച് പുറത്തുകടക്കുന്നു. ഓട്ടോമേഷന് അത്യാവശ്യം.
- **`--output-format json`:** ഗദ്യത്തിനു പകരം ഘടനാപരമായ ഔട്ട്പുട്ട്; തുടർന്നുള്ള ഘട്ടങ്ങൾക്ക് അത് വിശ്വസനീയമായി പാഴ്‌സ് ചെയ്യാം.
- **`--json-schema`:** ഒരു പ്രത്യേക JSON രൂപം ഉറപ്പാക്കുന്നു; ഉപയോഗിക്കുന്നവർക്ക് (ഉദാ: സ്വയമേവ ഇടുന്ന PR കമന്റുകൾ) പ്രതീക്ഷിക്കാവുന്ന ഫീൽഡുകൾ ലഭിക്കുമെന്ന് ഉറപ്പാക്കുന്നു.
- **സ്വതന്ത്ര review തത്വം:** കോഡ് ഉണ്ടാക്കിയ അതേ session അത് review ചെയ്യാൻ മോശമാണ് — അത് സ്വന്തം ന്യായവാദം ഓർക്കുകയും ന്യായീകരിക്കുകയും ചെയ്യുന്നു. review ഘട്ടങ്ങൾക്ക് എപ്പോഴും വേറിട്ട, സ്വതന്ത്രമായ ഒരു Claude ഉപയോഗിക്കുക.
