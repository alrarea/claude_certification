title: Plan Mode vs. Direct Execution

> **🔑️ പ്രധാന നിഗമനം:** Plan mode-ൽ Claude പ്രവർത്തിക്കുന്നതിനു മുൻപ് ഒരു പദ്ധതി നിർദേശിച്ച് അനുമതി വാങ്ങുന്നു; നേരിട്ടുള്ള നിർവഹണത്തിൽ നേരെ പ്രവർത്തിക്കുന്നു — വലുപ്പം, അവ്യക്തത, തെറ്റായ ഊഹത്തിന്റെ വില എന്നിവ നോക്കി തിരഞ്ഞെടുക്കുക.

- **Plan mode:** Claude ആദ്യം ഒരു പദ്ധതി കാണിക്കുന്നു, അനുമതിക്ക് കാത്തിരിക്കുന്നു, പിന്നെ നടപ്പാക്കുന്നു. ഉപമ: നിർമാണത്തിനു മുൻപ് പ്ലാൻ കാണിക്കുന്ന കരാറുകാരൻ.
- **നേരിട്ടുള്ള നിർവഹണം:** Claude ഉടനെ പ്രവർത്തിക്കുന്നു, മുൻകൂർ അനുമതി ഘട്ടമില്ല. ഉപമ: ചോരുന്ന ഒരു ടാപ്പ് ശരിയാക്കുന്ന കരാറുകാരൻ.
- **Plan mode ഉപയോഗിക്കേണ്ടത്:** വലിയ തോതിലുള്ള മാറ്റങ്ങൾ (45+ ഫയലുകൾ), architecture തീരുമാനങ്ങൾ, പല ശരിയായ വഴികളുള്ള സാഹചര്യങ്ങൾ, ലൈബ്രറി മൈഗ്രേഷനുകൾ, മൈക്രോസർവീസ് പുനഃക്രമീകരണം.
- **നേരിട്ടുള്ള നിർവഹണം ഉപയോഗിക്കേണ്ടത്:** ഒറ്റ ഫയലിലെ ലളിതമായ ബഗ് പരിഹാരങ്ങൾ, നേരായ ഒരു validation പരിശോധന ചേർക്കൽ, വ്യക്തവും നന്നായി മനസ്സിലാക്കിയതുമായ പരിഹാരങ്ങൾ, വേരിയബിൾ പേരുമാറ്റം, അക്ഷരത്തെറ്റ് തിരുത്തൽ.
- ശ്രദ്ധിക്കേണ്ട പ്രധാന സൂചന: വലുപ്പം + അവ്യക്തത + തിരിച്ചെടുക്കാനുള്ള എളുപ്പം. വലുത്, അവ്യക്തം, അല്ലെങ്കിൽ തിരിച്ചെടുക്കാൻ പ്രയാസം → plan mode. ചെറുത്, വ്യക്തം, എളുപ്പം തിരിച്ചെടുക്കാവുന്നത് → നേരിട്ടുള്ള നിർവഹണം.
