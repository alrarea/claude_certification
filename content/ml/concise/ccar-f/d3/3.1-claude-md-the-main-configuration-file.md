> **🔑️ പ്രധാന നിഗമനം:** Claude Code-ന് വേണ്ടി സ്വയമേവ ലോഡ് ചെയ്യപ്പെടുന്ന, സ്ഥിരമായ ഒരു നിർദേശ ഫയലാണ് CLAUDE.md; അത് എവിടെ വെക്കുന്നു (user / project / directory തലം) എന്നതാണ് ഒരു നിയമം ആർക്കൊക്കെ ബാധകമാകുമെന്ന് നിശ്ചയിക്കുന്നത്.

- ഓരോ session-ന്റെയും തുടക്കത്തിൽ CLAUDE.md സ്വയമേവ വായിക്കപ്പെടുന്നു — പ്രോജക്റ്റിന്റെ രീതികൾ ഓരോ തവണയും വീണ്ടും വിശദീകരിക്കേണ്ടതില്ല.
- **മൂന്ന് തലങ്ങൾ:**
  - User തലം: `~/.claude/CLAUDE.md` — വ്യക്തിപരം, പങ്കിടുന്നില്ല, git-ൽ ഇല്ല.
  - Project തലം: `./CLAUDE.md` അല്ലെങ്കിൽ `.claude/CLAUDE.md` — ടീം മുഴുവൻ, git-ൽ commit ചെയ്യുന്നു, എല്ലാവർക്കും ബാധകം. **ഏറ്റവും പ്രധാനപ്പെട്ട തലം.**
  - Directory തലം: ഒരു ഉപഫോൾഡറിനുള്ളിലെ `CLAUDE.md` — ആ ഫോൾഡറിൽ ജോലി ചെയ്യുമ്പോൾ മാത്രം ബാധകം.
- **സുവർണ നിയമം:** ടീം നിയമങ്ങൾ project തല ഫയലിൽ വേണം. ഒരു പുതിയ ഡെവലപ്പറുടെ Claude ഒരു നിയമം പാലിക്കുന്നില്ലെങ്കിൽ, സാധാരണ കാരണം ആ നിയമം അബദ്ധത്തിൽ ആരുടെയെങ്കിലും വ്യക്തിപരമായ user തല ഫയലിൽ വെച്ചു എന്നതാണ്.
- **വലിയ ഫയലുകൾ ക്രമീകരിക്കൽ:**
  - `@import filename.md` — മറ്റൊരു ഫയലിൽ നിന്ന് ഉള്ളടക്കം എടുക്കുന്നു.
  - `.claude/rules/` ഫോൾഡർ — ഓരോ വിഷയത്തിനും പ്രത്യേക നിയമ ഫയലുകൾ; CLAUDE.md ഏകദേശം 500 വരികൾ കടന്നാൽ ഉപകാരപ്രദം.
  - Glob അടിസ്ഥാനമാക്കിയ path scoping — പൊരുത്തപ്പെടുന്ന ഫയലുകൾക്ക് മാത്രം ഒരു നിയമം context-ലേക്ക് വരുന്നു (ഉദാ: `*.test.tsx`).
