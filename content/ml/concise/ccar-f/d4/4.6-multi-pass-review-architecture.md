> **🔑️ പ്രധാന നിഗമനം:** ഒട്ടേറെ ഫയലുകൾ ഒരൊറ്റ pass-ൽ review ചെയ്യുന്നത് ശ്രദ്ധ അസമമാക്കുകയും ഫയലുകൾക്കിടയിലുള്ള ബഗുകൾ വിട്ടുപോകുകയും ചെയ്യുന്നു — ഒരു per-file pass (പ്രാദേശിക പ്രശ്നങ്ങൾ), വേറിട്ട ഒരു integration pass (ഫയലുകൾക്കിടയിലുള്ള പ്രശ്നങ്ങൾ) എന്നിങ്ങനെ വിഭജിക്കുക.

- ഒട്ടേറെ ഫയലുകളിലൂടെ ഒരൊറ്റ സംയുക്ത pass → അസമമായ ശ്രദ്ധ; പിന്നീട് വരുന്ന ഫയലുകൾ കുറച്ചു ആഴത്തിൽ മാത്രം review ചെയ്യപ്പെടുന്നു.
- Pass 1 (per-file): ഓരോ ഫയലും പ്രാദേശിക ബഗുകൾ, ശൈലി, യുക്തി പിഴവുകൾ എന്നിവയ്ക്കായി വെവ്വേറെ review ചെയ്യുന്നു.
- Pass 2 (integration): ഫയലുകൾക്കിടയിലുള്ള പ്രശ്നങ്ങളിൽ മാത്രം ശ്രദ്ധിക്കുന്ന വേറിട്ട ഒരു pass — ഡാറ്റാ ഒഴുക്ക്, പങ്കിട്ട state, ഫയലുകൾക്കിടയിലെ API കരാറുകൾ.
- പ്രാദേശിക ബഗുകളും ഫയലുകൾക്കിടയിലെ ബഗുകളും വ്യത്യസ്ത തരം പ്രശ്നങ്ങളാണ് — ഒരൊറ്റ pass-ൽ കൂട്ടിക്കലർത്തിയാൽ രണ്ടും കണ്ടെത്താൻ പ്രയാസമാകും.
- Multi-pass-ന് ചെലവ് കൂടുതലാണ് (അധിക അഭ്യർഥനകളും orchestration-ഉം), പക്ഷേ ഒറ്റ pass review-കൾ സ്ഥിരമായി വിട്ടുപോകുന്ന പ്രശ്നങ്ങൾ ഇത് കണ്ടെത്തുന്നു.
- "പ്രാദേശിക വിലയിരുത്തലും ഇനങ്ങൾക്കിടയിലുള്ള വിലയിരുത്തലും വേർതിരിക്കുക" എന്ന അതേ തത്വം രേഖാ QA, moderation, മറ്റ് ബഹു-ഘടക review ജോലികൾ എന്നിവയ്ക്കും ബാധകമാണ്.
