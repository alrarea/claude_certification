title: Spawning Subagents — The Task Tool

> **🔑️ പ്രധാന നിഗമനം:** **Task tool** വിളിച്ചാണ് coordinator ഒരു subagent-നെ തുടങ്ങുന്നത് (അത് അതിന്റെ `allowedTools`-ൽ ഉണ്ടായിരിക്കണം); subagent-കളെ സമാന്തരമായി പ്രവർത്തിപ്പിക്കാൻ, ഓരോ turn-ലും ഒന്ന് വീതമല്ല, ഒരൊറ്റ പ്രതികരണത്തിൽ പല Task വിളികൾ നൽകുന്നു.

- ഒരു subagent-നെ തുടങ്ങുക = coordinator-ൽ നിന്നുള്ള ഒരു Task ടൂൾ വിളി; agentic loop-ലെ മറ്റേതൊരു ടൂൾ വിളിയും പോലെതന്നെ.
- **മുൻവ്യവസ്ഥ:** coordinator-ന്റെ `allowedTools`-ൽ `"Task"` ഉൾപ്പെട്ടിരിക്കണം — അല്ലെങ്കിൽ അതിന് ഒരു subagent-നെയും സൃഷ്ടിക്കാനാകില്ല.
- **സമാന്തര പ്രവർത്തനം:** *ഒരൊറ്റ* coordinator പ്രതികരണത്തിലെ പല Task വിളികൾ ഒരുമിച്ച് പ്രവർത്തിക്കുന്നു (സമയം ≈ ഏറ്റവും വൈകുന്നത്).
- **ക്രമാനുഗതം (ഒഴിവാക്കാമെങ്കിൽ തെറ്റ്):** ഓരോ turn-ലും ഒരു Task വിളി, ഓരോ ഫലത്തിനും കാത്തിരിക്കുന്നു — പരസ്പരം ബന്ധമില്ലാത്ത ജോലികൾ പോലും വരിയിലാകുന്നു.
- നല്ല ഒരു subagent prompt-ൽ എപ്പോഴും ഇവ ഉണ്ടാകും:
  - മുൻ agent-കളിൽ നിന്നുള്ള പ്രസക്തമായ എല്ലാ കണ്ടെത്തലുകളും (അല്ലാതെ subagent-ന് അവ കാണാനാകില്ല).
  - provenance നിലനിർത്താൻ ഉറവിട വിവരങ്ങൾ (URL-കൾ, രേഖയുടെ പേര്, പേജ് നമ്പർ).
  - ലക്ഷ്യങ്ങളും ഗുണനിലവാര പരിധിയും — കർശനമായ ഘട്ടം ഘട്ടമായുള്ള തിരക്കഥയല്ല; എങ്ങനെ എന്നത് subagent തീരുമാനിക്കട്ടെ.
- പരീക്ഷാ കെണി: "രൂപകൽപ്പന ചെയ്തിരിക്കുന്നത്" അങ്ങനെയാണെങ്കിലും ഒരിക്കലും ജോലി ഏൽപ്പിക്കാത്ത ഒരു coordinator — `allowedTools`-ൽ നിന്ന് `Task` വിട്ടുപോയിട്ടുണ്ടോ എന്ന് പരിശോധിക്കുക.
