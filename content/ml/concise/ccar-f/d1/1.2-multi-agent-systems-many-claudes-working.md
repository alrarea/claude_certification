title: Multi-Agent Systems — Many Claudes Working Together

> **🔑️ പ്രധാന നിഗമനം:** multi-agent സിസ്റ്റങ്ങളിൽ ഒരു coordinator, സ്വന്തമായി യാതൊരു context-ഉം ഇല്ലാതെ തുടങ്ങുന്ന subagent-കൾക്ക് കൃത്യമായ ജോലിഭാഗങ്ങൾ ഏൽപ്പിക്കുന്നു — അവരുടെ task prompt-ൽ വ്യക്തമായി എഴുതിയത് മാത്രമേ അവർക്ക് അറിയൂ.

- **Coordinator (orchestrator)** ആണ് യഥാർഥ മേൽനോട്ട ജോലി ചെയ്യുന്നത്: ജോലി വിഭജിക്കുന്നു, ഭാഗങ്ങൾ ഏൽപ്പിക്കുന്നു, subagent-കളുടെ പരാജയങ്ങൾ കൈകാര്യം ചെയ്യുന്നു, ഫലങ്ങൾ ചേർക്കുന്നു, വിവരങ്ങളുടെ ഒഴുക്ക് നിയന്ത്രിക്കുന്നു, ഏതൊക്കെ subagent-കൾ വേണമെന്ന് തിരഞ്ഞെടുക്കുന്നു.
- **Subagent-കൾ (workers)** ഓരോരുത്തരും ഒരു പ്രത്യേക ജോലി ചെയ്ത് തിരികെ റിപ്പോർട്ട് ചെയ്യുന്നു.
- **നിർണായക നിയമം:** coordinator-ന് അറിയാവുന്ന ഒന്നിലേക്കും subagent-കൾക്ക് **ഓർമയോ സ്വയമേവയുള്ള പ്രവേശനമോ ഇല്ല** — അവരുടെ task prompt-ൽ ഉള്ളത് മാത്രം. വിട്ടുപോയ context = subagent അത് ഒരിക്കലും അറിയില്ല, ഒരു ഇളവുമില്ല.
- **മൂന്ന് പാറ്റേണുകൾ:**
  - **Hub-and-Spoke** — coordinator-ഉം സ്വതന്ത്രരായ വിദഗ്ധരും; വ്യത്യസ്ത വൈദഗ്ധ്യം വേണ്ട ജോലികൾക്ക്.
  - **Pipeline** — ഒരു agent-ന്റെ ഫലം അടുത്തതിലേക്ക് പോകുന്നു; കർശനമായി ക്രമത്തിലുള്ള workflows-ന്.
  - **Peer-to-Peer** — agent-കൾ തുല്യരായി നേരിട്ട് സഹകരിക്കുന്നു; കൂട്ടായ പരിഷ്കരണത്തിന്.
- പരീക്ഷാ കെണി: ഒരു subagent-ന് അതിന്റെ prompt-ൽ ഒരിക്കലും നൽകാത്ത എന്തെങ്കിലും "എങ്ങനെയോ അറിയാമായിരുന്നു" എങ്കിൽ, അങ്ങനെയല്ല ഇത് പ്രവർത്തിക്കുന്നത് — പകരം coordinator-ന്റെ prompt എഴുത്ത് പരിശോധിക്കുക.
