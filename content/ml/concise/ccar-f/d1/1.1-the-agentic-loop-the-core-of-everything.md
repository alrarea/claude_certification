> **🔑️ പ്രധാന നിഗമനം:** agentic loop ഇതാണ്: ജോലി അയക്കുക → Claude ഒരു `stop_reason` സഹിതം പ്രതികരിക്കുന്നു → `tool_use` ആണെങ്കിൽ ടൂൾ പ്രവർത്തിപ്പിച്ച് ഫലം തിരികെ അയച്ച് വീണ്ടും ആവർത്തിക്കുക; `end_turn` ആണെങ്കിൽ നിർത്തുക — loop അവസാനിപ്പിക്കാനുള്ള *ഒരേയൊരു* സാധുവായ സൂചന `stop_reason` ആണ്.

- loop-ന്റെ ചക്രം: **ജോലി അകത്തേക്ക് → Claude ചിന്തിക്കുന്നു → `stop_reason` സഹിതം പ്രതികരണം → അതിന്റെ അടിസ്ഥാനത്തിൽ വഴി തിരിയുക.**
- കൃത്യമായി അറിഞ്ഞിരിക്കേണ്ട നാല് `stop_reason` മൂല്യങ്ങൾ:
  - `tool_use` — Claude ഒരു ടൂൾ പ്രവർത്തിപ്പിക്കാൻ ആവശ്യപ്പെടുന്നു; അത് നടത്തി ഫലം തിരികെ അയച്ച് വീണ്ടും ആവർത്തിക്കുക.
  - `end_turn` — ജോലി പൂർത്തിയായി; loop നിർത്തി ഉത്തരം നൽകുക.
  - `stop_sequence` — നിങ്ങൾ നിശ്ചയിച്ച ഒരു പ്രത്യേക നിർത്തൽ വാക്ക് വന്നു; നിങ്ങളുടെ ക്രമീകരണം അനുസരിച്ച് നിർത്തുക.
  - `max_tokens` — പ്രതികരണം മുറിഞ്ഞുപോയി; ഇത് ഒരു പിഴവായി കണക്കാക്കുക, അന്തിമ ഉത്തരമായി സ്വീകരിക്കരുത്.
- **ആന്റി-പാറ്റേണുകൾ (പരീക്ഷയിലെ കെണികൾ) — എപ്പോൾ നിർത്തണം എന്ന് തീരുമാനിക്കാൻ ഇവ ഒരിക്കലും ഉപയോഗിക്കരുത്:**
  - N ആവർത്തനങ്ങൾക്ക് ശേഷം നിർത്തുക (കൂടുതലോ കുറവോ ഘട്ടങ്ങൾ വേണ്ട ജോലികളിൽ ഇത് തകരും).
  - "done"/"finished" പോലുള്ള വാക്കുകൾക്കായി ടെക്സ്റ്റ് പരിശോധിക്കുക (വിശ്വസിക്കാനാകില്ല, വാക്കുകൾ മാറിക്കൊണ്ടിരിക്കും).
  - assistant ടെക്സ്റ്റ് ഉണ്ടെന്നത് ജോലി തീർന്നതായി കണക്കാക്കുക (Claude-ന് ടെക്സ്റ്റ് നൽകുകയും *അതേസമയം* ഒരു ടൂൾ ആവശ്യപ്പെടുകയും ചെയ്യാം).
- **ശരിയായ ഒരേയൊരു നിർത്തൽ വ്യവസ്ഥ:** `stop_reason == "end_turn"` ആണെങ്കിൽ മാത്രം loop അവസാനിക്കുന്നു.
- ടൂൾ പ്രവർത്തിപ്പിക്കുന്നത് *നിങ്ങളുടെ ആപ്ലിക്കേഷൻ കോഡ്* ആണ്, ഒരിക്കലും Claude നേരിട്ടല്ല — Claude അത് ആവശ്യപ്പെടുക മാത്രമേ ചെയ്യുന്നുള്ളൂ.
