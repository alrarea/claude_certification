title: Prompt Caching — Cost and Latency Optimisation

> **🔑️ പ്രധാന നിഗമനം:** ഒരേ prompt prefix-ന്റെ പ്രോസസ്സിങ് പല വിളികളിലായി വീണ്ടും ഉപയോഗിക്കുന്നതാണ് prompt caching — cache ചെയ്യാവുന്ന ഭാഗം പരമാവധിയാക്കി ചെലവും latency-യും കുറയ്ക്കാൻ സ്ഥിരമായ ഉള്ളടക്കം ആദ്യവും മാറുന്ന ഉള്ളടക്കം അവസാനവും വെക്കുക.

- ആവർത്തിക്കുന്ന ഒരേ ഉള്ളടക്കം (system prompt, ടൂൾ നിർവചനങ്ങൾ, റഫറൻസ് രേഖകൾ) caching ഇല്ലാതെ ഓരോ വിളിയിലും വീണ്ടും പ്രോസസ്സ് ചെയ്യപ്പെടുകയും അതിന് വീണ്ടും പണം നൽകേണ്ടിവരികയും ചെയ്യുന്നു.
- പൊരുത്തപ്പെടുന്ന ഒരു prefix-ന്റെ മുൻ പ്രോസസ്സിങ് വീണ്ടും ഉപയോഗിക്കാൻ caching Claude-നെ അനുവദിക്കുന്നു, പിന്നീടുള്ള വിളികളിൽ ചെലവും latency-യും ലാഭിക്കുന്നു.
- ക്രമ നിയമം: സ്ഥിരമായ ഉള്ളടക്കം (system prompt, നയങ്ങൾ, few-shot ഉദാഹരണങ്ങൾ) ആദ്യം; മാറുന്ന ഉള്ളടക്കം (user ചോദ്യം, ഓരോ വിളിയിലെയും ഡാറ്റ) അവസാനം.
- "സ്ഥിരം" എന്ന ഭാഗത്തിനുള്ളിലെ ഏത് മാറ്റവും, അല്ലെങ്കിൽ മാറുന്ന ഉള്ളടക്കം വളരെ നേരത്തേ വെക്കുന്നതും, prefix പൊരുത്തം തകർക്കുകയും അതിനു ശേഷമുള്ള എല്ലാറ്റിന്റെയും caching ഇല്ലാതാക്കുകയും ചെയ്യുന്നു.
- ഏറ്റവും വലിയ നേട്ടങ്ങൾ: നീണ്ട agentic loop-കൾ, പങ്കിട്ട റഫറൻസ് രേഖയുള്ള RAG, പങ്കിട്ട നിർദേശങ്ങളുള്ള വലിയ അളവിലുള്ള batch ജോലികൾ.
