> **🔑️ പ്രധാന നിഗമനം:** context പരിമിതമായതിനാലും അനിയന്ത്രിതമായ വളർച്ച ചെലവും ഗുണനിലവാരവും മോശമാക്കുന്നതിനാലും — എന്ത് prompt-ൽ നിൽക്കണം, എന്ത് സംഗ്രഹിക്കണം, എന്ത് പുറത്തേക്ക് മാറ്റണം, എന്ത് ആവശ്യമുള്ളപ്പോൾ മാത്രം ലോഡ് ചെയ്യണം എന്ന് സജീവമായി തീരുമാനിക്കുന്നതാണ് context window management.

- **Progressive summarisation**: ഇടം ലാഭിക്കാൻ പഴയ turn-കൾ ചുരുക്കുക — കൃത്യമായ വാക്കുകൾ നഷ്ടപ്പെടുന്നു.
- **External memory**: വിശദാംശങ്ങൾ prompt-ന് പുറത്ത് സൂക്ഷിക്കുക, ആവശ്യമുള്ളപ്പോൾ എടുക്കുക (RAG രീതിയിൽ) — retrieval latency കൂട്ടുന്നു.
- **Modular prompts / Skills**: പ്രസക്തമായ ഭാഗങ്ങൾ മാത്രം ലോഡ് ചെയ്യുക — മുൻകൂട്ടിയുള്ള ക്രമീകരണം വേണം.
- **Prompt caching**: സ്ഥിരമായ ഒരു prefix cache ചെയ്യുക — ആവർത്തിക്കുന്ന സ്ഥിര ഉള്ളടക്കം വിലകുറയ്ക്കുന്നു, പക്ഷേ അത് യഥാർഥത്തിൽ മാറാത്തതായിരിക്കണം.
- യഥാർഥ സിസ്റ്റങ്ങൾ തന്ത്രങ്ങൾ കൂട്ടിച്ചേർക്കുന്നു: cache ചെയ്ത modular system prompt + പുറത്തുനിന്നുള്ള retrieval + സംഗ്രഹിച്ച ചരിത്രം.
- സംഗ്രഹിക്കലാണ് ഏറ്റവും എളുപ്പമുള്ള തന്ത്രം, പക്ഷേ ഏറ്റവുമധികം നഷ്ടമുണ്ടാക്കുന്നതും — കൃത്യമായ ഓർമ പ്രധാനമാകുമ്പോൾ അപകടകരം.
