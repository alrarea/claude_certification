> **🔑️ പ്രധാന നിഗമനം:** പ്രസക്തമായ ഭാഗങ്ങൾ കണ്ടെത്തി generation-ന് മുൻപ് prompt-ൽ ചേർത്ത്, പുറത്തുള്ള കാലികമായ രേഖകളിൽ Claude-ന്റെ ഉത്തരങ്ങളെ അടിസ്ഥാനപ്പെടുത്തുന്നതാണ് RAG — Claude പരിശീലിച്ചത് ഇത് മാറ്റുന്നില്ല, inference സമയത്ത് അതിനോട് കൂട്ടിച്ചേർക്കുകയാണ് ചെയ്യുന്നത്.

- ആറ് ഘട്ട pipeline: **Ingestion → Chunking → Embedding → Indexing → Retrieval → Generation.**
- Ingestion തീരുമാനങ്ങൾ: ഏതൊക്കെ രേഖകൾ, എത്ര ഇടവിട്ട് പുതുക്കണം.
- Chunking തന്ത്രങ്ങൾ: നിശ്ചിത വലുപ്പം (ലളിതം/ഏകരൂപം), അർഥാധിഷ്ഠിതം/ഖണ്ഡിക (ആഖ്യാന രേഖകൾ), ശ്രേണീബദ്ധം (context + കൃത്യത), sliding window (അതിർത്തിയിൽ വിവരം നഷ്ടപ്പെടുന്നത് തടയുന്നു).
- Retrieval തന്ത്രങ്ങൾ: അർഥാധിഷ്ഠിതം/vector (ആശയപരമായ ചോദ്യങ്ങൾ), keyword/BM25 (കൃത്യമായ പേരുകൾ/കോഡുകൾ/ID-കൾ), **hybrid = മിക്ക പ്രൊഡക്ഷൻ സിസ്റ്റങ്ങളും**, re-ranking (കൂടിയ കൃത്യത, കൂടിയ latency).
- Generation ഘട്ടത്തിലെ തീരുമാനങ്ങൾ: എത്ര ഭാഗങ്ങൾ ഉൾപ്പെടുത്തണം, context-ൽ അവ എവിടെ വെക്കണം.
- പരീക്ഷാ മാതൃക: അർഥാധിഷ്ഠിത തിരച്ചിലിന് കൃത്യമായ കോഡുകളും ID-കളും വിട്ടുപോകുന്നു; keyword തിരച്ചിലിന് ആശയപരമായ പൊരുത്തങ്ങൾ വിട്ടുപോകുന്നു — hybrid തിരച്ചിൽ രണ്ടും പരിഹരിക്കുന്നു.
