title: Progressive Discovery vs. Monolithic Context
---
> **🔑️ പ്രധാന നിഗമനം:** Monolithic context എല്ലാം മുൻകൂട്ടി ലോഡ് ചെയ്യുന്നു (ലളിതം, വേഗം, പക്ഷേ ചെറുതും വ്യക്തമായി നിർവചിച്ചതുമായ രേഖാ ശേഖരങ്ങൾക്ക് മാത്രം പ്രായോഗികം); progressive discovery ആവശ്യമുള്ളത് മാത്രം ലോഡ് ചെയ്ത് ബാക്കി ആവശ്യാനുസരണം എടുക്കുന്നു (വലുതോ പ്രവചനാതീതമോ ആയ വിജ്ഞാന ശേഖരങ്ങളിലേക്ക് വളരുന്നു, കൂടുതൽ സങ്കീർണതയും ഓരോ ഘട്ടത്തിലെ latency-യും വിലയായി നൽകി).

- **Monolithic context:** എല്ലാം മുൻകൂട്ടി context-ലേക്ക് ലോഡ് ചെയ്യുക. generation സമയത്തെ വേഗതയാണ് പ്രധാനമെങ്കിൽ, ചെറുതും വ്യക്തമായി നിർവചിച്ചതുമായ രേഖാ ശേഖരങ്ങൾക്ക് ഏറ്റവും നല്ലത്.
- **Progressive discovery:** ആവശ്യമുള്ളത് മാത്രം ലോഡ് ചെയ്യുക, വേണ്ടപ്പോൾ കൂടുതൽ എടുക്കുക. വലിയ വിജ്ഞാന ശേഖരങ്ങൾക്കും പ്രവചിക്കാനാകാത്ത ചോദ്യ രീതികൾക്കും ഏറ്റവും നല്ലത്.
- Monolithic = ലളിതം, retrieval യുക്തി വേണ്ട, പക്ഷേ പ്രസക്തമല്ലാത്ത ഉള്ളടക്കത്തിന് token പാഴാക്കുന്നു, വളരുന്നില്ല.
- Progressive discovery = നന്നായി വളരുന്നു, പ്രവചിക്കാനാകാത്ത ചോദ്യങ്ങളോട് ഇണങ്ങുന്നു, പക്ഷേ architecture സങ്കീർണത കൂട്ടുന്നു, ആവർത്തിച്ചുള്ള retrieval മൂലം ഓരോ turn-ലും latency വരാം.
- പരീക്ഷാ സൂചന: ചെറുതും നിശ്ചിതവും അറിയാവുന്നതുമായ രേഖാ ശേഖരം → monolithic; വലുതും വളരുന്നതും പ്രവചിക്കാനാകാത്ത ചോദ്യങ്ങളും → progressive discovery.
