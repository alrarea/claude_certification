> **🔑️ പ്രധാന നിഗമനം:** Claude Code ക്രമീകരണങ്ങൾ ഒന്നിനുള്ളിൽ ഒന്നായ മൂന്ന് പരിധികളിലൂടെയാണ് തീരുമാനിക്കപ്പെടുന്നത് — Enterprise, Project, User — Enterprise ആണ് മറികടക്കാനാകാത്ത മേൽപ്പരിധി, User ആണ് ഏറ്റവും അകത്തുള്ള, ഏറ്റവും വ്യക്തിപരമായ തട്ട്.

- **Enterprise** — `managed_settings.json`; സ്ഥാപനം മുഴുവൻ; ഏറ്റവും ഉയർന്ന അധികാരം; IT/security-യുടെ ഉടമസ്ഥതയിൽ; താഴെയുള്ളവയ്ക്ക് മറികടക്കാനാകില്ല.
- **Project** — `./CLAUDE.md` + `.claude/rules/`; ആ പ്രോജക്റ്റിലുള്ള എല്ലാവർക്കും ബാധകം; കോഡിനൊപ്പം version control-ൽ.
- **User** — `~/.claude/CLAUDE.md`; ആ ഡെവലപ്പർക്ക് മാത്രം, അവരുടെ എല്ലാ പ്രോജക്റ്റുകളിലും.
- നിയന്ത്രിക്കുന്ന ക്രമീകരണങ്ങൾ (അനുമതികൾ, ടൂൾ പ്രവേശനം) മുകളിൽ നിന്ന് താഴേക്ക് ഒഴുകുന്നു, നിശ്ചയിച്ച ഏറ്റവും ഉയർന്ന തലത്തിലേത് ജയിക്കുന്നു.
- കൂട്ടിച്ചേർക്കുന്ന മാർഗനിർദേശം (ശൈലി, context) തട്ടുകളായി ചേരുന്നു; വൈരുധ്യമുണ്ടായാൽ പ്രോജക്റ്റ് നിയമങ്ങൾ വ്യക്തിപരമായ ഇഷ്ടത്തെ തോൽപ്പിക്കുന്നു.
- പ്രവർത്തന ശീലം: കോഡ് review-ൽ `.claude/rules/` പരിശോധിക്കുക; `managed_settings.json`-നെ ഡെവലപ്പർക്കുള്ള സൗകര്യ ഫയലായല്ല, ഒരു സുരക്ഷാ രേഖയായി കണക്കാക്കുക.
