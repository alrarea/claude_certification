> **🔑️ പ്രധാന നിഗമനം:** ജോലിയുടെ യഥാർഥ സങ്കീർണത എവിടെയാണോ, അതിനോട് ഇണങ്ങുന്ന വിഭജന അക്ഷം തിരഞ്ഞെടുക്കുക — functional, data, അല്ലെങ്കിൽ domain; multi-agent സിസ്റ്റങ്ങളിൽ വിട്ടുപോയതോ തെറ്റായതോ ആയ ഫലത്തിന്റെ ഒന്നാം കാരണം മോശം വിഭജനമാണ്.

- **Functional decomposition** — ഓരോ ഭാഗവും എന്ത് ചെയ്യുന്നു എന്നതനുസരിച്ച് വിഭജിക്കുക (research / write / review)
- **Data decomposition** — പ്രോസസ്സ് ചെയ്യുന്ന ഡാറ്റാ ഘടകം അനുസരിച്ച് വിഭജിക്കുക (ഓരോ രേഖയ്ക്കും/റെക്കോർഡിനും ഒരു agent)
- **Domain decomposition** — ബിസിനസ് മേഖല അനുസരിച്ച് വിഭജിക്കുക (legal / finance / HR agent-കൾ)
- രീതികൾ കൂട്ടിച്ചേർക്കാം (ഉദാ: ഓരോ രേഖയ്ക്കും data decomposition + ഓരോ രേഖയ്ക്കുള്ളിൽ functional decomposition)
- പരാജയ രീതി 1: ഭാഗങ്ങൾ ഇപ്പോഴും വളരെ വലുത് → ആവശ്യങ്ങൾ നിശ്ശബ്ദമായി ഒഴിവാക്കുകയോ പാതി മാത്രം പൂർത്തിയാക്കുകയോ ചെയ്യുന്നു
- പരാജയ രീതി 2: തെറ്റായ അക്ഷം തിരഞ്ഞെടുത്തു → സങ്കീർണത യഥാർഥത്തിൽ കുറയുന്നില്ല, ഗുണനിലവാര വിടവുകൾ പ്രത്യക്ഷപ്പെടുന്നു
- പരീക്ഷാ കെണി: "അപൂർണമായ/വിട്ടുപോയ ഫലം" എന്ന സാഹചര്യങ്ങൾ പലപ്പോഴും ഒരു വിഭജന പ്രശ്നത്തിലേക്കാണ് വിരൽ ചൂണ്ടുന്നത്
